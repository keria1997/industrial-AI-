# 库存管理模块缺陷

## BUG-INV-20260726-001 正式出库任务在库存校验后更换业务 ID

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P1 / 高 |
| 状态 | **开发已修复，待 QA 复验（2026-07-27）**；出库任务 ID 在校验前后保持稳定，出库单 ID 作为独立字段展示 |
| 涉及需求 | PRD 5.1、7.5.4、7.5.10；UC-012、UC-100 |
| 影响 | 同一个销售出库任务在销售、库存、生产之间无法使用稳定 ID 追踪，审计、重试和异常排查可能关联到不同对象 |

**复现步骤**

1. 创建并复核销售订单 `SO-20260726-F70B41B0`，产品 FG001，申请发货 150 PCS。
2. 从销售订单执行“保存并去发货”，进入库存出库管理。
3. 观察页面定位的出库任务为 `5d5ac483-da29-4c3d-aed3-637eb01b0a18`。
4. 执行“校验库存”并确认“校验并处理”。
5. 观察同一来源订单、产品和数量的任务变为 `d7b951c0-4d2b-41b5-b491-070d04f7b446`。

**实际结果**：库存校验前后页面把两个 UUID 都称为同一来源订单的“出库任务”，但没有显示临时任务到正式任务的映射，也没有保留原任务 ID。

**期望结果**：同一业务任务在创建、校验、生产申请、重新校验和发货阶段保持稳定 ID；若确有“发货申请”和“出库任务”两个聚合，页面和接口必须分别命名并展示稳定映射关系。



**开发修复（2026-07-27）**：

1. `mapFormalTask` 的 `id` 字段从 `task.outboundId || task.id` 改为始终使用 `task.id`（发货任务稳定 ID），`outboundId` 作为独立字段保留。
2. 出库管理表格 ID 列在稳定任务 ID 下方追加显示出库单 ID（仅当 `outboundId` 存在且与任务 ID 不同时显示），便于区分"发货申请"和"出库任务"两个聚合。
3. `refreshFormalTasks` 中 `formal.some((serverTask) => serverTask.id === item.id)` 匹配逻辑因 ID 稳定而不再产生重复条目。

**修改范围**：`src/App.tsx`。

## BUG-INV-20260726-002 待校验任务提前显示“可用 0 · 缺口 0”

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P2 / 中 |
| 状态 | 新发现，待开发修复 |
| 涉及需求 | PRD 7.5.4、7.5.5、7.5.10 |
| 影响 | 仓库人员可能把尚未读取权威库存事实的占位值误认为真实库存充足或无缺口 |

**实际结果**：新建销售出库任务状态为“待校验”时，列表同时展示“可用 0 · 缺口 0”；执行库存校验后真实结果为“可用 120 · 缺口 30”。

**期望结果**：权威库存校验完成前显示“待计算”或不展示可用量与缺口；校验完成后再展示事实版本、事实时间、可用量和缺口。



**开发修复（2026-07-27）**：

1. 出库管理表格可用量/缺口显示条件从 `Number.isFinite(Number(row.availableQty))` 改为区分正式任务和本地任务：
   - 正式任务且 `inventoryFactVersion == null`（尚未校验）：显示"待计算"，不显示可用量和缺口。
   - 正式任务且 `inventoryFactVersion != null`（已校验）：显示"可用 X · 缺口 Y"。
   - 本地任务：保持原有逻辑，有 `availableQty` 时显示。

**修改范围**：`src/App.tsx`。
