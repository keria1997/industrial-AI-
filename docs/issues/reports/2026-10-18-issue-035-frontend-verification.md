# ISSUE-035 前端实施与验证

日期：2026-10-18。范围：用户批准的前端修复及测试、Issue 记录。未修改后端、数据库、PRD、UI 或技术设计正文。

## 结论

前端按“组织/部门 → 员工 → 账号 → 唯一角色”完成本地实现与受控验证。本地真实只读页面检查通过；后端角色持久化、数据库唯一约束、真实会话角色来源尚未完成闭环验收，部署环境尚未通过新界面检查。整个 Issue 保持待联调/待复测。

## 实施内容

| 位置 | 行为 |
|---|---|
| 平台组织与员工 | 移除岗位入口、岗位编辑、岗位表格；组织详情展示直接归属员工及其账号角色 |
| 员工档案 | 删除岗位字段与岗位校验；按启用组织建档；人员模块档案展示同步删除岗位列和详情 |
| 员工与账号 | 开户和角色编辑使用必填单选 `roleId`，仅选择启用角色；员工已有账号时只维护原账号，包含停用、锁定及待激活状态 |
| 登录账号管理 | 新建表单以角色代替岗位；检查员工编号与登录账号重复；保留启停、重置密码、一次性初始密码功能 |
| 历史账号 | `directRoleIds` 一律提示待修正，不自动选择首项；缺角色、未知角色分别明确显示；不从岗位或工作台组继承权限 |
| 持久化 | 写入剔除岗位、角色数组和 UI 辅助字段；使用服务端版本；回读快照确认角色，不以 HTTP 成功代替绑定成功 |
| 组合开户 | 请求发送 `roleId`；响应未确认该角色时保留一次性密码并提示核实，勿重复创建 |
| 审批 | 来源仅有按角色、按组织负责人；候选人必须有有效唯一账号和启用角色；旧来源提示迁移，不自动改成组织负责人；“测试规则”仅预览配置 |
| 身份展示 | 侧栏、工作台、个人信息显示会话账号角色；菜单依旧使用服务端有效权限 |
| 工作台 | 未知/缺失角色不回退老板，也不请求老板指标；指标、预警、动态明确显示不可用，不无限加载；本人角色修改后重新取得签名会话与权限 |

前端不会写数据库；一员工一账号的并发与持久化唯一性必须由后端约束。

## 后端依赖与验收

实施期间共享工作区出现后端提交 `b8d1182`，随后由 `2899f51` 回退；不能将中间提交的说明当作最终交付。最终代码与运行服务需分开确认：

| 依赖 | 当前读取/观察 | 后续验收 |
|---|---|---|
| `POST/PUT /api/v1/platform/employees` | 当前控制器仍将 `primaryPositionId` 列为员工必填字段 | 无岗位字段即可创建/修改，组织归属持久化，回读一致 |
| `POST/PUT /api/v1/platform/accounts` 和快照 | 当前控制器仍补 `directRoleIds` 数组；单值角色修改已回退。运行快照含部分 `roleId` 数据，不证明保存逻辑一致 | 标量 `roleId` 必填，员工在职、角色启用、登录名及员工绑定唯一；不忽略前端 `roleId`；重登、回读一致 |
| `POST /api/v1/platform/employee-accounts` | 当前 AuthController 仍读取岗位；未解析/保存请求 `roleId`，响应未确认角色 | 同一事务建立组织员工、唯一账号与角色；返回 `employeeId`、`roleId`，列表与平台快照一致；明确组织 ID 契约，不能靠名称猜关联 |
| 登录/短信登录/刷新/有效权限 | 会话只有角色文本；当前测试账号未匹配到平台快照账号 | 签名身份、有效权限及角色展示来自同一租户账号的唯一角色；明确角色 ID、名称、工作台组映射；修改后生效 |
| 数据与审批迁移 | 当前源码仍含岗位与旧角色模型；未操作数据库 | 明确处理无角色、多角色、重复员工账号及旧审批规则；唯一约束覆盖全部账号状态，不能前端取首项 |
| PRD/UI/技术设计 | 不在本轮前端实施范围；此前后端/文档提交已回退 | 新模型、字段、权限与验收标准同步冻结后复核 |

可采用的错误分类：非法员工/非法或禁用角色为字段校验失败，员工重复绑定/登录名重复为冲突，旧版本为版本冲突，无权限为权限拒绝。具体错误码及 HTTP 契约由后端冻结；前端当前使用通用 API 错误提示并保留未提交草稿，不伪造后端结果。

## 完整闭环验收顺序

1. 后端交付并启动匹配的单角色契约；迁移方案独立评审，不直接操作真实业务库。
2. 在授权测试租户中建组织、员工，开户选择唯一角色；通过只读 SQL 核对员工组织、账号外键和唯一角色。
3. 覆盖重复开户、原账号停用后再次开户、无角色/多角色、失效角色与版本冲突，核对数据库没有产生错误绑定。
4. 修改原账号角色，确认回读快照、重登/刷新会话、有效权限、菜单、工作台指标均对应同一角色及数据范围。
5. 验证两条开户入口的初始密码、激活、启停、重置与权限生效一致，审批规则按唯一角色或组织负责人执行。
6. 发布前端后，在部署环境复测桌面、移动端及完整链路；上述条件满足后再关闭 ISSUE-035。
