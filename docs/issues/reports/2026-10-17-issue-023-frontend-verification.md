# ISSUE-023 前端修复与验证报告

- 日期：2026-10-17
- 结论：前端本地已修复；部署待更新复测。
- 范围：前端显示、提示、查询恢复与入库路径引导；未修改后端代码或数据库。
- 实施授权：展示方案后，用户明确回复“实施”。

## 修复结果

| 缺陷 | 本轮实现 |
|---|---|
| DEF-A 缺库存/接口错误显示产品 ID | 按正式产品主数据映射名称和编码；服务端错误仅替换已知产品身份，不篡改其他诊断信息 |
| DEF-B 缺处理引导 | 缺事实持续警告，提供同仓重查、库存台账及入库办理指引；不再把缺事实解释为必须换仓 |
| DEF-C 产品字段显示 ID | 列表、详情、发货与生产缺口明细统一名称/编码；主数据缺失显示明确未知状态 |
| DEF-D 入口无响应 | 挂载入库办理指引，支持采购收货与生产完工入库跳转；按钮按有效权限显示 |
| 原手工入库草稿误用快照导入 | 删除组件中的 `importAvailability` 调用、固定数量组成和事实版本，取消虚假入库成功反馈 |

展示映射保持稳定 `productId`、订单行 ID、任务版本、单位和数量不变。保留合法部分发货、不允许分批、无事实和单位不一致等守卫。对同产品重复多行，按逐行缺事实情况判断全部缺失，避免去重产品数与行数比较造成误判。

独立手工入库提交未实现，前端目前明确提示暂不可用。后端需先提供实际入库契约，明确：

- 来源单据、仓库/产品身份、单位、数量、权限及数据范围。
- 版本冲突、幂等与结果未知的查询恢复方式。
- 增量过账与库存快照的区别；保留已有预留、冻结、安全库存事实。
- 成功结果中的入库流水、库存事实版本及可供前端回读的记录。

部署更新后，还需在具备可匹配产品和合法测试数据的授权租户重跑受控与真实页面场景。涉及写入闭环应使用隔离测试数据，不用快照导入制造库存解除业务阻断。
