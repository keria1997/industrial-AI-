# 产品库存仓库可选关联

- 记录日期：2026-10-17
- 来源：用户要求先记录 issue，再修改前端。
- 范围：库存管理 → 产品 → 新增产品、修改产品，仅修改前端。
- 状态：前端已实现；真实仓库关联保存与新增可空的后端条件尚待验收。

## 问题与需求

1. 产品表单仓库字段目前被锁定，无法关联仓库。
2. 字段标签统一为“库存仓库”，不使用“库存归属仓库”。
3. 新增产品时允许不关联仓库；选择关联时只能关联一个仓库。
4. 修改产品时可以选择并保存关联仓库，重新打开后应回显服务端保存的结果。
5. 未关联时明确显示未关联，不得以第一个仓库或库存分布推导替代产品配置。

## 实施与验收要求

- 先核对现有产品读写接口对 `defaultWarehouseId` 的支持，不改动后端。
- 选项来自后端返回的授权仓库，不能使用浏览器原型数据。
- 验证新增不关联、新增选择仓库、修改关联、保存后回显和失败保留输入。
- 无可选仓库时新增产品仍可不关联仓库；已关联停用仓库应可识别，不能静默替换。
- 仓库配置变更不应在前端生成调拨、库存增减或财务事实。
- 若接口未支持持久化，明确记录阻断，不以本地保存冒充成功。

## 处理结果

- 已将产品表单和产品列表标签改为“库存仓库”。新增默认“暂不关联”，可选择一个启用仓库；编辑未关联产品可补充关联，已关联产品可改选其他启用仓库。
- 候选仓库来自正式 API；前端将所选仓库转换为服务端 ID，通过产品 POST/PATCH 提交。保持现有配置时不重复提交仓库字段，避免因原仓库停用而阻断其他资料修改。
- 产品关联直接读取 API 的 `defaultWarehouseId`，不再从单仓库存事实推导。未关联显示“未关联”；不可用的现有关联保留标识，禁止静默替换。
- 保存后重新查询来源事实。HTTP 错误保留草稿；成功响应未确认所选关联时，明确提示“产品资料已提交，但库存仓库关联未确认，请刷新后检查”，不以本地配置伪造成功，也不盲目重复创建。
- 调整销售开单的库存匹配，兼容同一仓库的服务端 ID 与编码，避免产品配置接入后将已有库存误显示为零。该调整不增加任何库存事实。
- 关联仓库未查询到库存事实时，产品列表实际可用显示“-”，不将关联本身视为零库存事实。

- `npm run test:frontend`：31 个测试文件、157 项测试通过。
- `npm run typecheck`、`npm run build` 通过；构建仍有现有的大包及动态导入提示。
- Playwright 受控接口回归覆盖：新增不关联、新增关联、编辑关联及刷新回显、停用仓库回显、无可选仓库、HTTP 错误保留草稿、成功响应缺少关联确认。受控结果不代表真实后端持久化已验收。
- 现有库存编辑器焦点回归通过；真实登录只读回归覆盖仓库、产品、物料表单输入和刷新后焦点保持，无业务写入。
- 真实页面只读检查：4 个可选仓库，新增默认空值，编辑选择器可用；390px 和 1440px 视口检查通过。当前运行的产品 GET 返回 7 个产品，均未包含 `defaultWarehouseId`，需后端确认新接口实现已部署并补齐回读。
- 真实 API 的关联持久化、新增不关联及数据库一致性未在本任务验收；本任务未修改后端代码或直接操作数据库。

## 接口核对

- 前端沿用 `POST /api/v1/inventory/products`、`PATCH /api/v1/inventory/products/{id}`，关联值 `defaultWarehouseId` 传仓库服务端 ID；读取为空或缺失时显示未关联。
- 新增不选择仓库时省略该字段，不自动补默认值；编辑新选仓库时提交该字段，未改关联时省略字段、保留原配置。编辑已关联产品本次不增加解除关联功能。
- 初检时 `FulfillmentService.createMaster` 无条件校验必填仓库，与“新增不关联”冲突；最终复核发现工作区其他改动已增加产品空仓库写入 `null` 的处理。本任务未修改该后端文件，源码变化不能替代运行接口验收。
- 后端待确认：部署后产品新增允许字段缺失或空值并回读未关联状态；非空值继续校验租户、授权、存在性和启用状态。新出现的 `docs/openapi/backend/v1/inventory-master.yaml` 在本次复核时仍将产品创建的 `defaultWarehouseId` 列为必填，需与可选规则同步。此条仅记录，不在本任务修改后端或其契约。
- 本次用户的“新增可不关联”取代旧技术说明书 §10.4.1 中“产品新增必须选择仓库”的约束；物料不在本次变更范围。
