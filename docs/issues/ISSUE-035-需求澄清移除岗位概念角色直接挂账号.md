# ISSUE-035：需求澄清——移除岗位概念，角色直接挂账号且一账号一角色

- 级别：P0 模型变更
- 模块：平台管理
- 层级：L4 基础层
- 影响范围：前端, 后端, PRD, 设计文档
- 状态：🔴 待修复

## 问题

当前系统引入了"岗位（Position）"概念，通过 `iam_position` 表的 `default_role_ids[]` 实现岗位→角色的间接授权链路。但业务需求澄清后确认：

1. **系统中不存在"岗位"这个概念**
2. **组织和部门用来管理员工**（员工归属组织，不归属岗位）
3. **一个员工只能有一个账号**（1:1 关系）
4. **角色直接挂在账号上**（不经由岗位中转）
5. **一个账号只能有 1 个角色**（非多角色）

这与当前实现存在根本性冲突：

| 冲突点 | 当前实现 | 正确模型 |
|---|---|---|
| 岗位 | `iam_position` 表 + `default_role_ids[]` | **不存在的概念** |
| 角色→账号 | 通过岗位间接继承 + `direct_role_ids[]` 多角色 | 仅 `direct_role_ids[1]`（单角色） |
| 员工→账号 | 1:1 但可通过多岗位间接多角色 | 严格 1:1 |
| 组织 | 组织→岗位→员工 | 组织/部门→员工 |

## 原因

需求分析阶段错误引入了 HR 系统中常见的"岗位"概念，但本项目为轻量级 B2B ERP，用户管理模型应为扁平化的"组织→员工→账号→角色"关系，不涉及岗位层级。

## 方案

### 后端

| 改动 | 文件 | 说明 |
|---|---|---|
| 移除岗位表 | `iam_position` 表 | DROP 或标记 deprecated |
| 移除岗位种子数据 | `TenantCatalog.java` | 删除 `orgUnits()` 中的岗位定义、`ADMIN_POSITION_ID` |
| 角色改为单选 | `iam_account.direct_role_ids` | 从 `text[]` 改为 `text`（单个角色 ID） |
| 角色解析简化 | `PlatformService.java` | 移除通过 `position.defaultRoleIds` 获取角色的逻辑 |
| 移除岗位 API | `PlatformController.java` | 删除岗位 CRUD 接口 |

### 前端

| 改动 | 文件 | 说明 |
|---|---|---|
| 移除"新增岗位"弹窗 | `PlatformManagement.tsx` | 删除岗位创建 UI |
| 组织树移除岗位节点 | `PlatformManagement.tsx` | 组织树下仅显示员工，不显示岗位 |
| 账号创建改为单选角色 | `PlatformManagement.tsx` | 角色下拉仅选 1 个 |

### PRD

| 改动 | 章节 |
|---|---|
| 移除岗位概念定义 | 第 7.13 节、第 8 章 |
| 组织模型改为"组织/部门→员工→账号→角色" | 第 7.13 节 |
| 角色矩阵改为一账号一角色 | 第 7.2.3 节 |

### 设计文档

| 改动 | 章节 |
|---|---|
| 移除岗位相关 UI 组件 | 组织与岗位页签 |
| 组织与岗位改为组织与员工 | 页签重命名 |

## 验收标准

1. 系统中不存在"岗位"相关的表、API、UI 组件
2. 组织与部门用于管理员工（员工归属组织，不归属岗位）
3. 一个员工只能有一个账号（数据库唯一约束）
4. 角色直接挂在账号上（不经由岗位中转）
5. 一个账号只能有 1 个角色（`direct_role_ids` 为单个值非数组）
6. 工作台按账号的唯一角色展示对应指标和菜单
7. PRD 和设计文档中不再出现"岗位"概念
