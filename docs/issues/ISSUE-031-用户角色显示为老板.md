# ISSUE-031：用户角色为租户管理员但界面显示为老板

- 级别：P1 体验
- 模块：工作台 / 认证
- 层级：L4 基础层
- 影响范围：前端, 后端
- 状态：⏭️ 前端已修复，后端岗位字段待联调

## 问题

原问题记录：用户 `liyi` 的员工主岗位为“租户管理员”，但侧栏和工作台均显示“老板 · 经营驾驶舱”，与平台管理中的主岗位不一致。本轮未查询或修改该用户的数据库记录。

复现步骤：

1. 使用 `liyi` 账号登录。
2. 查看侧栏用户信息及工作台角色标识，旧界面显示“老板 · 经营驾驶舱”。
3. 进入平台管理的员工与账号页面，对比账号关联员工的主岗位。

## 原因

1. 当前后端 `AuthController.SessionUser` 仅提供 `role`，没有实际员工主岗位的展示字段。不能将 `role` 直接替换为任意岗位名称：它还用于既有会话及工作台分组链路。
2. 前端 `AppRuntimeProvider.resolveSessionRole()` 将会话角色转换为工作台角色组，不识别的值回退为“老板”。因此即使后端直接返回 `role: "租户管理员"`，旧界面仍会显示“老板”。
3. `App.tsx` 将 `activeRole` 同时用于工作台查询和侧栏、工作台、个人信息展示，混用了工作台角色组和员工主岗位。
4. 当前实际菜单访问使用 `permissions.ts` 的有效权限集合判断。本次不修改权限规则，也不通过岗位名称授予菜单访问权。

原方案中“前端无需修改”和“用实际岗位替换 role”的结论作废。本问题与 ISSUE-034 的岗位展示部分重叠，但本轮仅实施已确认的 ISSUE-031 前端范围。

## 方案

| 修改层面 | 文件 | 具体改动 |
|---|---|---|
| 前端 | `frontend/src/api/session.ts` | 声明可选 `displayPosition?: string \| null`。沿用现有响应展开，账号登录、短信登录、刷新和会话恢复均保留服务端字段；不合并旧岗位 |
| 前端 | `frontend/src/app/AppRuntimeProvider.tsx` | 声明展示岗位字段，明确 `activeRole` 及其回退值仅表示工作台展示分组 |
| 前端 | `frontend/src/app/userIdentityPresentation.ts` | 统一主岗位展示规则，缺失时显示“岗位信息未提供”，不从账号、角色、权限或员工列表推断 |
| 前端 | `frontend/src/App.tsx` | 侧栏、工作台标识、个人信息分别展示主岗位和工作台视图；岗位名称支持换行 |
| 前端测试 | `frontend/src/app/tests/sessionPosition.test.ts`、`userIdentityPresentation.test.ts`、`frontend/tests/userIdentity.e2e.mjs` | 覆盖认证字段流转、空值及异常值、权限不变、刷新、账号切换、租户范围和移动端展示 |
| 后端依赖，未实施 | `backend/src/main/java/com/wanshen/platform/auth/AuthController.java` 等身份组装代码 | 登录及刷新响应增加实际员工主岗位字段 `user.displayPosition`，保留 `role` 的既有含义；岗位来源必须与当前租户下账号关联员工的主岗位一致 |

### 字段契约与缺失策略

- `role`：保留工作台现有角色组处理及接口参数，不替换为员工任意岗位名称。
- `displayPosition`：可选字符串或 `null`，仅用于主岗位展示；前端去除首尾空白。示例：`role: "老板"`，`displayPosition: "租户管理员"`。
- 只有会话唯一授权租户与当前租户一致时，标量 `displayPosition` 的归属才无歧义。多租户会话暂显示“岗位信息未提供”；后端需另行明确按租户返回岗位的契约后再支持，不能把某租户岗位沿用到另一租户。
- 字段未返回、`null`、空串、空白、非字符串或租户归属不明确，三处均显示“岗位信息未提供”。无占位假岗位，不通过 `role` 或权限反推，不额外请求整个人员/平台列表。
- 侧栏及工作台显式标注“主岗位：…”和“工作台视图：…”。例如主岗位是租户管理员时，工作台视图仍可为经营驾驶舱；视图名称不表示实际职务或新增权限。
- 刷新/重新登录以新响应为准，不沿用旧响应岗位；无需新增浏览器业务缓存或清理已有正式认证会话。

## 验收标准

1. 单租户会话返回 `displayPosition: "租户管理员"` 时，侧栏、工作台和个人信息均显示该主岗位；工作台名称另列展示。
2. 岗位字段缺失或无效时，显示“岗位信息未提供”，不把工作台回退组“老板”显示为用户实际岗位。
3. 登录、短信登录、刷新、会话保存/恢复保留新字段，旧会话没有该字段时仍能正常登录和展示缺失状态。
4. 账号切换、岗位变更或新响应缺少岗位时不保留旧岗位；多租户归属未明确时不跨租户展示。
5. 菜单与命令仍以有效权限判断；实际岗位为管理员但只有工作台读取权限时，不显示平台管理菜单。
6. 工作台查询继续发送既有有效 `role` 分组，不发送“租户管理员”等岗位名称。
7. 桌面和移动端岗位内容可读，长名称换行，不超出容器。
8. 后端交付岗位字段后，使用 `liyi` 真实登录，与平台管理的关联员工主岗位逐项对比；需完成部署环境验证才可关闭整个 Issue。
