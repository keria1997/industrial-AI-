# ISSUE-024：生产需求 BOM 阻断恢复、暂缓入口及 Toast 时序

> 原编号：ISSUE-019；2026-10-17 索引整理后改为 ISSUE-024。
> 发现日期：2026-10-17
> 原环境：http://124.222.114.67/（部署环境）
> 模块：生产管理 → 主计划 (MPS)
> 级别：P1 恢复流程 + P2 体验
> 状态：前端已修复、本地真实闭环已验证；原部署数据待核实。

## 1. 原现象

需求 `DM-MVCBRHE4D10A` 校验提示“缺少服务端生效 BOM”；暂缓按钮仅提示“暂缓审批尚未开放”；生产提示约 3 秒消失。

## 2. 核实后的原因

| 现象 | 原因与修正 |
| --- | --- |
| 缺 BOM 阻断 | `ProductionService.validateDemand` 按租户和稳定 `productId` 查询 BOM。未命中返回 `BLOCKED`；命中但工艺关联/工序不完整仍阻断。这是正式业务守卫。原部署数据库尚未核对，不能直接断言该产品没有记录 |
| 无法完成维护恢复 | 旧 BOM 表单要求手填 ID，容易与显示编码混淆；缺少携带产品上下文、返回原需求和重新校验的页面闭环。该风险不能单独证明原部署需求的根因 |
| 暂缓只弹提示 | 两处入口调用占位处理器；当前没有冻结的需求 hold/resume 契约与状态规则，不能声称某个猜测接口“未对接” |
| Toast 过早消失 | 生产提示固定 3000ms，新增提示未清理旧计时器，旧计时器可能提前关闭新提示；不能只全局替换时间数字 |

## 3. 已实施

1. 从阻断需求进入正式 BOM 维护，绑定并锁定真实产品 ID；使用正式物料、库存仓库和工作中心选择器，按权限加载。
2. 现行命令直接发布 `EFFECTIVE` BOM 和内嵌工艺，不增加“先存草稿再发布”流程。发布成功与回读失败分别表达。
3. 返回原需求保留筛选和定位，读取最新版本，等待用户主动重新校验。仅服务端 `PENDING_REVIEW` 表示通过，发布本身不推进需求状态。
4. 校验请求发送 `{}`，移除四项写死的主数据通过声明；补齐行内错误、同步请求锁、版本冲突回读和身份切换隔离。
5. 发布失败保留输入；结果未知先回读，必要时保留原请求、版本和幂等键重试；冲突要求读取并核对最新版本。
6. 需求池和 MPS 的暂缓按钮均禁用，显示“暂缓暂未开放”，删除可点击的假操作。
7. 生产 Toast 改为完整 5 秒，替换、关闭、卸载和身份切换均清理计时器；持续阻断原因保留在行内。

本次没有后端代码改动。其他模块 Toast 时长不调整。

## 4. 验证和剩余边界

- 类型检查、224 条单测、构建通过；受控 Playwright 验证闭环、权限、冲突、未知结果、移动布局与提示时序。
- 本地隔离租户真实操作验证 UI→API→PostgreSQL：无 BOM 为 `BLOCKED v2`；发布后 BOM/工艺一致且需求仍阻断；重新校验成为 `PENDING_REVIEW v3`，强刷新一致。
- 原部署需求不在本地隔离租户可见范围，不能认定原数据已修复；部署版本和实际数据仍须在原环境核实。
- 暂缓/恢复能力、产品/工厂启用校验的权威事实来源仍待业务和后端明确。
- 扩展数字输入回归发现销售快速开单的既有仓库标识不一致，单独记录在实施报告，不纳入本次生产修复。
