### 1.1 状态定义

| 状态 | 判定标准 |
| --- | --- |
| 已完成 | 目标范围内的前后端或独立能力可执行，数据和规则有可靠实现，关键路径有测试 |
| 部分完成 | 只完成部分子能力，或只有前端/后端一端，尚不能完成端到端业务 |

### 2.1 PRD 核查结论

PRD 章节完整，但从研发可执行性和当前代码对齐角度仍有以下缺口。首期销售—库存—生产—发货的目标契约已在交付基线补齐；表中“待实现”仍必须通过 OpenAPI、迁移、代码和测试落地：

| 编号 | 核查发现 | 影响 | 建议 |
| --- | --- | --- | --- |
| PRD-GAP-001 | 第 7 章大量模块复用通用模板字段 | 首期之外模块仍无法直接形成精确 DTO 和表结构 | 首期销售/库存/生产字段已在交付基线补齐；采购、财务等后续域仍需分别补充 |
| PRD-GAP-002 | PRD 使用 `PROD_CREATE/APPROVE` 等界面权限码，生产后端使用 `production.work-order.*` 等资源动作权限码 | 前端按钮、网关和服务端可能口径不一致 | 建立统一权限码映射，以后端资源动作码为权威契约 |
| PRD-GAP-003 | PRD 生产页面包含设备与成本分析；生产 P0 迁移测试明确排除 equipment/cost 等 P1 占位表 | 容易误判为 P0 已交付 | 设备与成本保持原型/P2，独立评审数据源和领域归属 |
| PRD-GAP-004 | 当前代码只有生产域稳定 UUID、correlationId、幂等和事件字段 | 首期跨域运行仍不能真实闭环 | 首期 SO、预留、出库和完工事件/DTO、OpenAPI 和数据库开发基线已批准，进入实施；PR/PO、AR/AP 不在首期 |
| PRD-GAP-005 | 当前库存投影只接收汇总 `availableQty`，没有组成项和口径版本 | 现有实现仍无法审计销售可履约量公式 | 基线已冻结“合格现存 - 预留/分配 - 冻结 - 安全库存”、排除在途及字段契约；待实现 Adapter 和新投影 |
| PRD-GAP-006 | 外部系统仍未实际联调 | 客户端点、认证、映射和 SLA 尚不能验收 | 首期已冻结 WMS 权威和 HTTPS JSON API + 事件方式；实施期补客户连接配置，ERP/MES/财务的扩展范围后续评审 |
| PRD-GAP-007 | PRD 要求权限变更即时生效并强审计，当前平台状态只在浏览器保存 | 上线存在越权和不可追溯风险 | 将平台 IAM 服务端化后再认定平台管理 P0 完成 |
| PRD-GAP-008 | PRD 验收要求性能、兼容、安全和埋点，但没有测试数据规模、压测模型或埋点 schema | 非功能验收无法重复执行 | 补充容量模型、测试环境基线、埋点事件字典和验收脚本 |
| PRD-GAP-009 | 当前没有销售订单、库存预留/出库正式聚合 | 目标状态仍无法形成可信服务端事实 | 聚合、状态、权限、API、事件、迁移和补偿开发基线已批准；立即实施，不得继续用本地回写代替 |

上述问题不阻止当前原型演示。首期业务设计、OpenAPI、数据库和技术默认值已经通过联合评审，销售/库存可以进入正式开发；真实客户连接、UAT 和上线仍分别受联调、测试与运维门槛约束。其他业务域继续按各自缺口补规格。
