# 后端业务逻辑盘点

本文按当前代码阅读结果整理各模块业务逻辑。后续 JPA 重构必须保持业务行为不变，只替换持久化和 DTO 形态。

## 1. 销售与履约

### 1.1 主要入口

| 类 | 职责 |
| --- | --- |
| `FulfillmentController` | 销售订单、库存、发货任务、出库、采购、主数据等入口 |
| `SalesFulfillmentController` | RMA、客户签收、销售完成、SLA、报价、销售监控 |
| `FulfillmentService` | 销售订单状态机、库存预留、出库过账、缺货转生产、采购链路 |
| `SalesAftercareService` | RMA 状态机、客户签收、红字 AR、销售完成关闭 |

### 1.2 核心业务

1. 销售订单创建后进入确认/复核状态机。
2. 发货申请触发库存检查与预留；可部分预留，缺货时创建生产需求。
3. 出库过账扣减库存并回写销售订单已发数量；全部发货后进入 `SHIPPED`。
4. 出库事实驱动发货确权 AR；客户签收是独立事实。
5. 收款确认生成核销事实，核销更新 AR 余额；全部核销后 AR 结算。
6. RMA 独立于原销售订单状态，经过申请、审批、物流、收货、检验、回入库、红字 AR 和关闭。
7. 销售完成要求全部发货、客户签收、AR 结算、无未关闭 RMA/争议。

## 2. 库存与采购

当前与销售同属 `fulfillment` 模块。

1. 库存事实包括合格现存、预留、冻结、可用量、安全库存和事实版本。
2. 发货任务按行预留和出库；库存不足时可转生产或采购。
3. 采购链路为 PR 审批、PO 创建、多次收货、检验和入库。
4. 采购退货需要关联原收货并生成负向库存和 AP 事实。
5. 手工入库、调拨、盘点必须形成库存流水，不允许直接修改可用量。

## 3. 生产

### 3.1 主要入口

| 类 | 职责 |
| --- | --- |
| `ProductionController` | 需求、工单、BOM、报工、FQC、完工、结案入口 |
| `ProductionService` | 生产状态机和业务校验 |
| `ProductionStore` / `JdbcProductionStore` | 当前 JSON 聚合持久化 |

### 3.2 核心业务

1. 生产需求来源包括销售缺货和手工需求。
2. 需求经历校验、审批、接收、MRP、APS、工单创建。
3. 工单要求 BOM、工艺、工厂、工作中心和仓库快照。
4. 工单经历计划、齐套、下达、开工、暂停、完工和结案。
5. 报工累计良品、不良、报废和投入数量，并执行数量守恒。
6. FQC 处理合格、返工、报废和复检。
7. 完工先创建 `POSTING` 任务，库存结果成功后才更新为 `POSTED`。
8. 结案前检查报工、检验、完工和库存事实。

## 4. 财务

1. 出库确权生成 AR；采购合格入库生成 AP。
2. 收付款先登记后确认；确认人不能等于登记人。
3. 确认直接关联 AR/AP 时生成系统 Allocation；独立核销必须检查 Payment 和 AR/AP 剩余额度。
4. 冲销生成反向事实并按 Allocation 恢复余额，不直接篡改历史事实。
5. 发票、凭证和成本归集是财务投影或补充事实。

## 5. 平台

1. 租户注册初始化租户、组织、员工、账号、角色、授权、字典和参数。
2. 组织用于管理员工；账号直接绑定唯一角色。
3. 角色授权决定菜单、按钮、API、字段和数据范围。
4. 审计记录必须与业务写入同事务保存。
5. 字典用于设备类型、健康状态等可维护选项。

## 6. 消息

1. 消息记录来自业务事件，不承载业务终态。
2. 模板、用户偏好和订阅控制发送方式。
3. 已读和归档不改变来源业务状态。
4. Outbox Worker 负责投递和失败重试。

## 7. 人员

1. 员工归属部门/组织。
2. 人员档案、考勤和技能资料是独立事实。
3. 人员考勤不是 IAM 授权依据。

## 8. 产业链

1. 供应商、客户和风险事件服务采购与销售风险展示。
2. 供应商和客户使用稳定 ID，禁止按名称猜测关联。

## 9. AI

1. 模型配置控制 AI 服务调用。
2. 会话和消息保存交互历史。
3. 洞察和行动计划是业务数据的只读分析投影。
4. AI 结果不直接推进业务终态。

## 10. 工作台

1. 工作台是只读聚合，不维护独立业务状态。
2. 指标、待办、预警和动态均来自权威业务事实。
3. 缺失事实必须显示不可用，不允许伪造零值或完成状态。
