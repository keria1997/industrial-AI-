## 2026-10-17 前端完整性审查整改

- 范围仅前端与配套文档，不修改后端业务代码，不清理数据库。完整闭环 P0 需求仍有效；下列“不可用”是诚实的依赖状态，不等于功能交付完成。

## 2026-10-17 原型缓存反复出现的修复

- 根因：入口仅清除 4 个固定版本 localStorage 前缀，遗漏 sessionStorage、历史版本与库存 workflow、平台状态；模块挂载会自动回写快照，库存异常解析与生产初始化还会恢复代码内种子。
- 处理：入口扫描两个存储区域的退役业务键；开发与生产均阻止退役键重新读写；移除销售、生产、平台的自动业务快照保存。
- 固定数据：清空主应用 23 组示例数组与生产原型 5 组记录；移除库存主数据及平台种子回退。测试数据隔离至 `frontend/src/app/tests/fixtures/`。
- 正式数据：销售选品与库存主数据从正式库存 API 加载；平台使用完整 API 快照，不再仅覆盖角色、权限后混入示例组织及员工。
- 保留：登录会话、租户选择、出库幂等信息、正式生产记录 ID 索引；不删除数据库任何记录。浏览器缓存按访问源隔离，访问对应地址并刷新后自动执行清理。
- 未接入项：平台管理中仍只在内存更新的旧保存动作，以及库存产品/物料编辑器中的本地保存/删除，不再冒充持久化成功，显示未保存/未删除提示。本次未修改后端，也未宣称上述功能已完成 API 对接。
- 仓库归属：产品/物料没有库存事实时，不伪造默认仓库；多仓事实无法确定唯一默认仓库时也不任取第一仓。默认仓库配置和按仓选品仍需按正式接口契约继续完善。
- 验证：156 条前端单元测试、类型检查和生产构建通过；`npm run test:prototype-storage` 在开发服务和生产预览分别验证 11 个页面的接口空数据/不可用场景，共 44 次页面检查通过。浏览器测试使用受控 API 响应，不代表完成数据库端到端验收。
