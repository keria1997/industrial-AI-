## 1. 文档说明

本文件将 PRD 的角色和业务场景转换为可开发、可测试的用户用例。状态含义：

- `已支持`：当前存在可执行正式实现。
- `部分支持`：只有部分步骤或只有一端实现。
- `原型支持`：页面可演示，但没有正式后端事实。
- `未支持`：当前无实现。

首期客户交付只验收“销售—库存—生产—发货”：从销售订单待发货（历史兼容名称为待确认）开始，经过复核/审批、确认内容进入已确认、去发货移交、库存校验、缺货生产、完工入库、重新校验和部分/全量出库，到订单全量发货结束。采购和财务结算不作为首期闭环完成条件，详细范围见 `docs/首期交付基线-销售库存生产发货.md`。

### 3.2 会话验收口径

#### UC-001 登录、恢复会话与退出

1. 非生产环境用户使用允许的开发账号和密码登录，服务端签发带账号、权限和授权租户的 8 小时签名令牌。
2. 前端把令牌保存到 `sessionStorage`，后续请求自动携带 Bearer Token 和当前租户。
3. 刷新当前标签页后恢复会话；令牌过期或服务端返回 401 时清理会话并回到登录页。
4. 切换租户时，服务端确认该租户在令牌授权范围内；越权租户返回 403。
5. 退出时清理令牌和当前会话。有效手机号可获取验证码，不要求预先绑定账号；已绑定禁用账号不能获取。点击获取验证码经火山引擎SendSms受理后显示查收提示；登录仍要求手机号绑定启用账号，不自动创建账号或映射演示管理员。验证码5分钟有效、一次性使用，新码替换旧码。每手机号60秒最多获取一次、每分钟最多5次验证，正式模式不回传验证码。

验收：伪造 `X-Actor-Id` 或 `X-Permissions` 不能获得权限；生产环境未配置 `AUTH_SECRET` 时拒绝启动，且演示登录始终关闭。

当前边界：火山引擎验证码发送及已有账号手机号登录已实现；发送受理与运营商送达分别判断，不自动重发未知结果。企业 SSO/OIDC、完整刷新/撤销与密码治理仍未完成；工作角色切换仍是前端原型。

#### UC-003 查看角色工作台

1. 用户必须具备 `workbench.dashboard.read`；无权限时导航隐藏工作台，URL直达和API返回403。
2. 服务端按当前会话角色和数据范围返回指标：老板看租户全量；销售看授权客户/订单的订单金额、确认收入和发货确权金额；计划员看授权工厂/计划的交期达成量和授权仓库物料低水位；仓管看授权仓库物料低水位。无权限指标隐藏，缺事实显示“-”，不显示伪造0。
3. 订单金额按本月未取消销售订单统计；确认收入按确认收入事实统计；发货确权金额按实际出库过账事实统计，部分发货只计实际过账部分。
4. 排产交期达成量只统计交期前实际完工过账量与计划量的较小值；晚交不计入；跨单位无批准换算时按单位分组，不静默相加。
5. 低水位只统计授权仓库内的物料，判定为`合格现存-已分配/预留-冻结 < 安全库存`；同物料跨仓去重。
6. 业务预警只读来源业务状态，不依赖AI服务生成或关闭；处理时跳转来源单据，由来源模块业务命令更新状态。
7. 待办限于PRD 7.2.3目录：销售复核/审批、销售确认、生产需求接收、发货任务重检、写入结果未知、PR审批和收付款确认。每条待办有稳定ID、来源ID、责任人、优先级、跳转参数和版本；只有目录中的来源业务事实能关闭待办。
8. 实时动态提供“全部业务事件”和“关键事件”范围；两者只包含已登记业务事件的授权投影，覆盖来源模块、来源ID、业务状态、发生时间和版本；重复事件去重；页面浏览、搜索和登录埋点不进入。
9. 页面每5分钟自动刷新或手动刷新；响应必须携带数据截止时间、生成时间和来源事实版本；网络异常只展示已确认快照并标注过期。

验收：`AC-PH1-040~052` 全部通过且有API/集成及客户UAT证据。当前原型不能因页面可见而标记为已支持；完整指标、待办目录和事件投影仍待实现。

#### UC-006 主导航进入默认首页并按 URL 刷新恢复

1. 点击左侧主导航或使用移动端模块选择进入模块，打开该模块第一个页面；销售、生产、库存、采购、财务、人员默认选中监控舱。

3. 生产历史计划或其他后台业务数据延迟恢复时，更新展示数据但不改变当前页面；监控舱保持选中。
4. 用户明确执行采购申请、生产计划、入出库等业务跳转时，打开操作指定的目标页面，并保留需要的单据定位；`production=plan` 兼容进入主计划 MPS。

### 3.3 销售需求与现状验收口径

#### UC-010 创建并维护报价

1. 进入 `?module=sales&tab=quotes`，刷新后仍停留在产品报价。
2. 新建报价进入草稿，可保存草稿或执行生效；草稿/生效中且未转单的报价可软作废，过期报价只能查看或生成新版本。
3. 客户与销售经理线下确认报价后，由客户经理在线执行“审批确认并转订单”；只有生效中、未过期且未转单的报价可操作，默认同一报价只成功转单一次。报价每次编辑保存后版本递增，确认转单时必须重新读取该报价最后一次保存的数据，不能使用打开确认弹窗时的旧数据。
4. 转单成功生成总体状态为待确认、发货状态为未发货的销售订单；订单完整复制最新报价的客户、报价日期、有效期、多行产品、仓库、规格、单位、数量、单价、可用量参考、折扣率、优惠金额、报价总额和备注，并保存报价稳定 ID、版本及独立快照。报价后续变化不得静默覆盖已生成订单；报价标记已转订单并关联订单号，转单动作不得提前触发库存校验、出库或发货。
5. 列表按编号、客户、状态、销售人员、日期、有效期和转单状态由服务端筛选；默认按更新时间倒序。
6. 金额使用十进制口径，校验客户、产品、数量、价格、折扣底线和数据权限；提交中禁止重复操作。

当前边界：页面已有查看、编辑、新增、有效期、金额、编辑版本递增和最新报价快照转单原型，但状态仍主要按日期派生为正常/过期，行操作与 PRD 的生效、作废和正式新版本流程不完整；记录保存于租户命名空间的版本化 `localStorage`，无报价后端、并发版本和正式审计。

#### UC-012 销售订单复核、发货申请与仓库移交

来源校验：生产流程未关联来源销售订单号时，不生成销售订单列表行；不得把“业务来源”、空产品和零金额的流程占位信息显示为业务订单（2026-10-13 用户要求移除空测试订单）。

真实持久化验收：快速开单的日期、有效期、备注和每行名称/规格均由订单 API 校验并保存，清除租户销售缓存后重新查询，所有字段仍应恢复；无效日历日期、有效期早于开单日期及超长文本返回 400。缺少创建权限返回 403，同键同请求恢复已有订单，重载 JDBC 仓储后仍只有一张订单且没有发货任务。

快速开单验收：与“新增报价单”共用客户、日期/有效期、仓库、多产品明细、优惠和备注表单。创建直接调用销售订单 API，逐行保留产品、数量、单位和价格，传递折扣及优惠总额；不得只传第一行或回退到默认产品/仓库。正式 API 当前一张订单对应一个发货仓库，混仓提交提示选择同一仓库。成功后关闭弹窗，进入订单页并选中“待发货”，清空旧搜索和客户筛选；状态由服务端 `PENDING_CONFIRMATION`/`NOT_REQUESTED` 返回，不在创建时审批、确认或发起发货。失败保留输入，提交中阻止重复点击，未改内容的重试复用幂等键。

权限验收：当前角色无库存模块访问权限，或会话不含 `inventory.shipment-task.read`/`*` 时，发货成功弹窗不显示“进入出库管理”；订单行、更多操作和详情入口均保留申请发货及关闭弹窗的能力。有上述权限时，点击按钮才进入库存出库并定位订单，导航处理复用同一权限判断。

1. 进入 `?module=sales&tab=orders`，首期正式筛选包含“待确认、已确认、生产补货中、部分发货、已发货、已取消”，并按客户过滤；“已完成”只作为未来/历史只读兼容状态。
2. 新建或报价转单后总体状态为待确认；确认/审批状态按租户规则独立流转，复核或审批通过不改变总体状态。总体状态为待确认且发货状态为未发货时允许编辑客户、销售人员、产品明细、订单金额、订单日期和交期；订单号、总体状态、发货状态、应收金额及报价来源留痕不可编辑。内容确认成功即锁定编辑能力，即使尚未移交仓库也不能退回编辑。
3. 待发货订单只有在复核/审批完成后才显示“确认订单”；点击后打开“确认销售发货内容”弹窗，展示客户、销售人员、订单日期、产品明细、库存参考、数量、价格和优惠汇总。交期校验通过后订单进入已确认，但不创建仓库任务。
4. 已确认订单显示“去发货”；点击后幂等生成或恢复仓库任务，仅展示“已通知仓库准备发货”弹窗，URL 和当前销售页面不变。用户点击“我知道了”或关闭按钮后继续停留销售页面；仅点击“进入出库管理”才跳转并定位来源订单。订单行、更多操作、详情和剩余发货入口遵循同一交互，失败不得展示成功弹窗或跳转。仓库重新校验订单版本、可发数量、数据范围和最新库存事实；原子创建或补足原任务预留和出库单，零已发且全部剩余可发时为已确认，已有实际出库保持部分发货。缺口只阻断未覆盖数量，允许分批的有效预留部分仍可发。
5. 仓库核对缺口并成功发起生产申请后，零已发订单进入生产补货中；已有实际出库的订单保持部分发货。该阶段不允许修改、删除、取消或撤回。
6. 完工入库后按新版本库存事实重新校验。库存满足时补足预留/出库单；零已发订单回到已确认，已有实际出库的订单保持部分发货。仍有缺口时仅阻断缺口，允许分批的有效预留部分可发，补货状态不覆盖已有部分发货状态。
7. 仓库部分出库时总体状态和发货状态进入部分发货，准确汇总已发/未发数量；只允许查看或对未发数量执行“发起剩余发货”。全量出库后进入已发货。
8. 已发货订单只读，是首期成功终点；签收、财务结算和 `COMPLETED` 为后续范围。待确认订单只有在没有活动申请、预留、生产需求、出库或其他不可逆事实时可填写原因取消。
9. 首期详情展示总体状态、确认/审批状态、发货状态、订单行已发/未发、库存事实组成和时间、预留、出库单、生产需求、工单、完工、版本、Correlation ID 和 Trace ID；应收信息不作为首期必备字段。
10. 销售订单表格横向滚动时，“操作”列固定在可视区域右侧；查看、发货和更多操作按钮不得要求用户先横向滚动才能访问。“更多操作”菜单点击菜单外任意区域或按 `Esc` 后关闭，点击菜单内动作不得被误判为外部点击。
11. 同一订单在待发货、审批完成、已确认及刷新后金额一致；报价或历史订单建立正式聚合时保存折扣率和优惠金额，多行明细完整保留。服务端以十进制计算优惠后总额并校验前端预期金额，不一致时阻断保存；仅编辑交期不能清空明细或改变金额。
12. 销售订单从待发货经履约进入已发货后，出库管理中必须可查关联的已完成记录。正式订单复用服务端出库事实；历史本地已发货订单保存时自动同步，直接进入出库管理也补齐缺失记录。按来源销售订单去重、保留已有出库单号、多行合计数量，刷新和确认收货不新增单据或重复扣库存；待发货、已确认、部分发货和已取消订单不作为全量已出库记录补齐。

2026-10-14 首期阻断修订补充：

- 内容确认后锁定，未移交、已预留未发、部分发货均不能退回编辑/取消/删除/撤回；前端与直接API均拒绝，任务及预留不变。异常只走原因必填、异人复核的补偿事实，原订单仍锁定。
- 原任务使用工作流、可用量、补货、过账四轴；允许分批且存在有效预留时，可以在剩余补货中发预留部分，不把库存不足标签作为全面禁发条件。
- 全部库存充足但主动发4/10时，只扣4并消费预留4，原任务继续处理剩余6；不允许分批时不得主动少发。数量超限拒绝、不静默截断；可以0跳过行但整次不得全0。
- 自由可用已扣所有预留，本任务可发上限需合并本任务未消费有效预留，不能把该预留再次计为缺口。过账同时扣现存和预留，重算自由可用，不额外再减一次。
- 已发4/10后剩余6补货、入库、预留和重校验均保持部分发货；只在实际出库剩余6后已发货。订单累计与本任务累计分别保存，原任务未终结优先恢复，不能重复占用剩余量。
- 数量守恒、场景初始化及明确断言见 PRD 7.5.12.9～7.5.12.10、13.1.3；订单完成逐行判定，不将不同单位求和作为完成依据。

当前边界：待发货操作列提供“确认订单”，正式确认接口固化交期并进入已确认；确认成功自动切换已确认筛选并显示服务端订单状态。报价转单和历史本地订单在确认时以稳定幂等键创建正式订单，记录原单号关联并更新报价关联单号；创建后读取最新版本，再按权限完成审批和确认，失败不得显示确认成功。确认阶段不创建仓库任务；已确认订单“去发货”才创建正式任务并展示弹窗，由用户手动进入出库管理。重新进入销售和刷新时以服务端状态为准，旧缓存和业务流展示不得覆盖正式订单状态。报价、客户和基础数据仍有租户隔离的前端原型。

复测补充：合法交期输入会即时清除字段错误并提交订单确认；正式仓库出库以 API 返回的 `task`、`order` 更新列表，返回销售和刷新均读取持久化已发/剩余量与状态。本地桥接仅保留历史兼容路径，不驱动正式出库或虚构应收。库存预留后的首次出库使用新出库单 ID；部分出库后补货沿用原单和行标识，已消费行不再提交。

单位兼容验收：已有正式订单为 1 台、成品主仓事实为 5 PCS 时，预留 1、实际出库 1，库存剩余 4 PCS，销售累计已发 1 台；原幂等键重试不增加流水或再次扣减。件/个适用同一单件规则。订单为套/箱/KG 而库存为 PCS 时，前端展示单位差异并阻断，后端返回 422，库存、预留、出库和销售均不变。完工入库单件别名可增加库存一次，新事实及流水单位为 PCS。

销售到仓库独立验收步骤：创建两行正式订单（5 PCS、3 PCS）并审批，确认后仓库任务数为 0；两次“去发货”复用同一任务且保持销售页面，手动进入出库。库存为 3 PCS、3 PCS，第一次发货为 2 PCS、3 PCS，销售回写部分发货及剩余 3 PCS、0 PCS。补充新版库存事实后继续发货 3 PCS，最终同一任务完成，累计 5 PCS、3 PCS，申请占用和未消费预留归零，库存流水为 3 条；返回和刷新后均已发货且不可再次发货。禁止分批、超量、重复行、失败回滚、同键重试及跨实例库存竞争另由自动化测试覆盖。

#### UC-013 维护客户和销售基础数据

1. 客户列表按名称/编码、信用代码、行业、等级、合作状态、归属销售和资料完整性筛选，并受租户、组织和归属销售数据范围限制。
2. 客户名称和统一社会信用代码执行租户内查重；至少维护一个主联系人，联系人支持职位、决策角色和一对多矩阵。
3. 客户归属销售为空时进入公海；停用客户不可用于新报价和订单，历史单据仍可追溯，停用原因必须留存。
4. 客户等级支持阈值、状态和排序；定时任务只生成升降级建议，不自动覆盖人工等级。
5. 行业字典为可停用的树形结构；被引用节点不得物理删除。SLA 规则配置监听状态、阈值、通知对象、渠道、升级阈值和启停状态，扫描和通知必须幂等。
6. 销售人员不可进入基础数据页；销售主管只能调整授权阈值和启停状态；系统管理员维护字典结构，操作销售业务仍需显式业务权限。

当前边界：客户、联系人、字典和触达配置均为租户隔离的本地原型；缺少服务端查重、联系人矩阵、公海/停用规则、分级权限、定时建议任务、消息通道和 ERP 企业数据辅助核验。

#### UC-034 维护仓库并查看库存内容

1. 用户进入库存管理的仓库页，按编码、名称、类型、组织、负责人和状态搜索仓库。
2. 用户新建仓库，填写唯一编码、名称、类型、组织、负责人、地址、容量、状态和备注；编辑时编码只读。
3. 用户点击仓库名称或“库存内容”进入详情，查看仓库信息、库容使用率、产品/物料种类数和库存条目数。
4. 用户在库存内容中切换全部、产品、物料，并按编码、名称、规格或库位搜索；列表展示现有量、冻结/预留量和实际可用量。
5. 产品/物料已分配该默认仓库但没有后端库存事实时，数量显示 `-` 和“未查询到库存记录”；后端明确返回零库存时显示 `0`。仓库详情、现存量、发货校验和实际扣减使用同一事实，仓库编码及服务端 ID 指向同一仓库，不按名称匹配。
6. 已被库存、默认仓库或活动单据引用的仓库不可删除，只能停用；停用仓库不得用于新业务。

当前边界：仓库列表、创建/编辑/删除及引用保护使用正式主数据 API；仓库详情和现存量使用履约库存事实。加载及错误状态不得显示预置数量，失败可重试。正式库存不提供只改页面的编辑、删除和快速盘点入口。产品/物料维护和补货申请仍保留既有本地路径；客户 WMS、正式分页/导出和完整调拨/盘点流程未验收。

#### UC-035 维护产品和物料主数据

1. 用户分别进入产品或物料页，按编码、名称、规格、分类/类型、默认仓库和状态筛选。
2. 新建产品需填写唯一编码、名称、规格、分类、基本单位、默认仓库、安全库存、追溯方式和状态。
3. 新建物料需填写唯一编码、名称、规格、物料类型、基本单位、默认仓库、采购策略、安全库存和状态。
4. 仓库、产品和物料编码在租户内跨类型查重；编辑时编码不可修改，停用仓库不能作为默认仓库。
5. 保存后，对象立即出现在其默认仓库的库存内容中；默认仓库变更只改变默认分配，不自动调拨既有库存。
6. 已有库存事实或业务引用的产品/物料不可删除，只能停用并保留历史关系。

当前边界：产品和物料维护、租户隔离持久化、跨类型编码校验和默认仓库展示为前端原型；正式主数据 API、数据库、审计、权限及与销售/BOM/采购联动待后续阶段实现。

| 主要参与者 | 销售专员/主管、仓库操作员/主管、生产计划员/主管、采购制单人/审批人、车间操作员、质检员/质量主管、Reference WMS Adapter |
| 前置条件 | 用户已认证；最小客户/产品引用、Reference BOM、工艺、工厂、工作中心和仓库有效；角色权限和数据范围已配置 |
| 触发 | 待发货销售订单完成复核/审批后，由销售确认发货内容；随后从已确认列表去发货并移交仓库 |
| 成功后置 | 首期订单逐行全量实际出库、`SHIPPED`且来源可追溯；有缺货生产时MRP/APS、工单、完工/结案及重校验可追溯。PR/PO/采购入库仅为缺料Reference扩展场景附加条件，不是所有首期场景必需 |
| 当前状态 | Reference 闭环已支持；完整供应商/价格/分批收货、复杂 MRP/APS 和客户 ERP/SRM/WMS 联调仍未完成 |

主成功路径：

1. 销售创建最小可履约订单；审批开启时由非制单人审批，关闭时状态为 `NOT_REQUIRED`。审批只改变独立审批状态，总体仍为 `PENDING_CONFIRMATION`。
2. 销售执行“确认订单”，服务端固化交期和发货内容并进入 `CONFIRMED`，不创建仓库任务；随后执行“去发货”，按剩余数量幂等发布仓库任务。
3. 库存域或 WMS 原子重读权威库存，按“合格现存 - 已分配/预留 - 冻结 - 安全库存”计算可履约量；在途不计入，并保存组成项、口径版本和事实版本。
4. 库存足够时原子预留并创建/恢复销售出库单，零已发保持 `CONFIRMED`、已有实际已发保持 `PARTIALLY_SHIPPED`；允许分批时先预留可用部分并记录缺口。
5. 存在缺口时由仓库显式发起生产申请。生产域按来源行版本幂等创建或恢复生产需求；订单在零已发时进入 `REPLENISHING`，已有出库时保持 `PARTIALLY_SHIPPED`。
6. 按PRD文首现行授权完成需求校验/审批，再由授权计划员接收并运行MRP；不能因审批成功省略接收。物料缺口存在时阻断APS/工单。
7. 首期由人工补料/外部权威物料事实满足齐套；缺料Reference扩展场景中采购制单人创建PR，另一账号审批生成PO，收货产生唯一入库流水并同步新物料事实；该扩展不把完整采购域纳入首期退出。
8. 物料齐套后运行 APS；创建工单时服务端再次读取权威物料库存并派生齐套状态，随后下达、开工和报工。
9. 质检员执行 FQC；通过后提交生产完工入库，Reference WMS 产生唯一库存流水和新版成品库存事实，并关联原发货任务。
10. 原任务按新事实重校验并合并本任务未消费预留；零已发缺口归零才回已确认，已有实际出库始终部分发货。仍有缺口时仅缺口阻断，允许分批的有效预留部分可发。
11. 仓库按本次实际确认量出库，不能强制发全部预留。唯一WMS流水同时扣现存、消费等量预留并重算自由可用，再累计订单/任务各行已发；全部订单行等于订购量才 `SHIPPED`。

替代路径：

- A1：成品库存足够时跳过生产，直接预留并发货。
- A2：允许分批时先发已预留数量，剩余缺口继续生产；不允许分批时整次申请保持阻断。
- A3：物料不齐套时阻断 APS/工单；Reference 闭环通过 PR/PO/采购入库补料，客户环境也可由 ERP/SRM/WMS 同步权威新事实。
- A4：FQC 不通过时进入返工或审批报废，禁止完工入库。
- A5：WMS 返回未知时保持 `PROCESSING_UNKNOWN/POSTING` 并使用原幂等键重查；明确拒绝才进入 `FAILED`。
- A6：完工后仍缺货时缺口继续阻断、有效预留按分批守卫可发；追加生产需求使用新来源版本并保留原需求，已有已发不降级。
- A7：事件重复或乱序时 Inbox 去重并等待缺失版本，不重复累计已发数量。

验收要点：

- 所有下游事实保留来源单号/行号、租户、责任人、时间和 Trace ID。
- 同一写请求重复提交不生成重复单据。
- 无权限用户看不到或无法执行动作；URL 直达也必须由后端阻断。
- 任一节点失败时保留已确认事实和输入，提供可追踪的重试/补偿入口。
- 原“物料已齐套”的首期场景仍不强制出现 PR/PO；本次缺料扩展场景必须出现 PR、PO 和采购入库，且不得用前端状态替代正式事实。AR/AP、收付款、发票、凭证和 `COMPLETED` 仍不在成功口径。

### UC-014 仓库出库缺货发起生产申请

| 项目 | 内容 |
| --- | --- |
| 主要参与者 | 仓库管理员、库存系统、生产计划员 |
| 前置条件 | 销售订单总体为已确认或部分发货，销售已执行去发货形成仓库任务；库存服务已发送当前产品和仓库的可用量事实；仓库用户有 `inventory.production-request.create` |
| 触发 | 仓库执行销售出库时发现可用库存不足，并点击“发起生产申请” |
| 成功后置 | 保存销售接入决策；缺货时保存可追溯生产需求，库存充足时不创建生产需求 |
| 当前状态 | 部分支持；库存事实复核和生产需求事务创建为正式能力，销售订单、出库任务与状态回写仍是前端原型 |

主路径：

1. 库存系统发送带 `eventId`、`factVersion`、产品、仓库、可用量、单位和事实时间的事件。
2. 生产接入服务以 Inbox 去重，只有更高版本可以更新库存事实投影。
3. 仓库端以稳定幂等键提交订单号、行号、来源版本、产品、数量、单位、交期、工厂和仓库，不提交自报缺口作为权威事实。
4. 服务端读取库存事实，不接受销售端自报可用量或缺口。
5. 服务端使用十进制字符串计算缺口。
6. 缺货时，在同一事务中创建接入记录、生产需求、来源关系、状态历史、审计、Outbox 和幂等响应。
7. 目标销售域在需求创建成功后，若累计已发为 0 则把订单总体状态更新为生产补货中，已有实际出库则保持部分发货；当前前端使用响应中的真实需求 UUID/编号、接入记录和库存事实版本更新本地出库任务与“生产中”状态，并可在生产需求池重新查询该需求。

出库管理列表提供“销售订单号”搜索框，按表格“来源 / 目标单据”的显示值（`source`）即时筛选，支持完整单号、部分单号、忽略大小写及首尾空格。清空后恢复全部已加载任务并将焦点返回搜索框；记录总数跟随筛选结果，无匹配时显示“没有匹配的来源 / 目标单据”。搜索不修改订单、任务、库存或 URL，不改变销售发货成功后只展示弹窗、由用户手动进入出库管理的规则。

出库弹窗按选定仓库的库存事实展示动作：

1. 任务产品在选定仓库没有库存事实时，立即提示“[仓库名]没有该产品：[产品编码]”，禁用确认发货，不提交预留。
2. 产品存在且本任务剩余全部可发时，主按钮为“确认发货”；允许分批时可以调小，按实际量回写。
3. 服务端合并本任务未消费预留和自由可分配库存后仍无任何可发量时，主按钮为“去生产”；自由可用0但本任务已有预留时不适用。
4. 允许分批且至少一行可发、存在缺口时，展示“确认部分发货”和“缺口去生产”；即使所有行都未全量满足也可部分出库。
5. 订单或任务行禁止分批时，即使存在部分可用量也保持“去生产”，不得拆分发货。

替代与异常路径：

- A1：库存充足时不创建生产需求；原任务原子补足预留/出库单，零已发保持/恢复已确认、已有实际已发保持部分发货。兼容生产接入接口本身不承担订单确认/库存过账。
- A2：库存事实不存在、过期或单位不一致时返回 424；事务回滚，不创建需求、接入记录或 Outbox。
- A3：同一幂等键和请求重复提交时回放原响应，不创建第二条需求。
- A4：同一订单行版本使用新幂等键重试时恢复既有接入结果；修改业务数据必须提升来源版本。
- A5：重复库存事件由 Inbox 去重；陈旧 `factVersion` 不覆盖当前事实。

验收要点：缺货量必须来自库存事实版本；数据库中需求来源指向销售订单行；需求和 Outbox 原子提交；租户之间不可读取或覆盖库存事实和接入记录。

## 5. 生产域详细用例

生产管理前端当前以 `LegacyProductionManagement` 为唯一用户批准入口，旧版页面内不挂载 `ProductionOperations` 整页。以下用例中的“已支持（API）”表示正式后端和类型化客户端能力存在，不代表正式作业整页已经挂载。未经用户明确批准，验收不得以整体替换生产模块的方式接入这些能力；入口保护测试必须保持通过。

### UC-020 创建生产需求

前置条件：请求含有效 Bearer Token、令牌授权租户、`production.demand.create` 权限和幂等键。

主路径：

1. 提交来源类型、产品、数量、单位、交期和工厂资源。
2. 服务校验十进制数量、日期和工厂字段。
3. 在事务内创建 `RECEIVED` 需求、来源、审计、状态历史、Outbox 和幂等记录。
4. 返回 201、需求版本和 Trace ID。

异常：相同幂等键不同请求体被拒绝；缺少/过期令牌返回 401；租户越权或无权限返回 403。

### UC-021 校验并审批生产需求

1. 计划员提交产品、工厂、BOM 和工艺有效性结果。
2. 存在阻断项时需求进入阻断状态并返回修复原因。
3. 校验通过后具备审批条件。
4. 需求审批默认与制单人分离；持已发布 `production.mps.view` 授权的制单人可审批本人需求，`*` 最高权限同样允许，明确拒绝优先。审批成功更新版本并记录审计。

### UC-023 创建并下达工单

1. 创建工单并保存产品、工厂、工作中心、数量、交期和需求分配。
2. 调用下达影响预览，查看 BOM/工艺、APS 和齐套阻断项。
3. 修复阻断后，以最新 ETag 下达工单。
4. 服务记录状态转换、审计和 Outbox。

异常：版本不一致时拒绝；分配数量非法、快照缺失或齐套不满足时不得下达。

### UC-025 报工与更正

1. 已开工工单提交合格、不良、报废、投入数量和单位。
2. 服务校验累计产出不超过累计投入和计划上限。
3. 报工以不可变事实记录并更新工单累计量。
4. 更正时保留原记录，创建替代记录和更正原因。

验收：不使用 JavaScript 浮点数判断业务数量；重复提交不产生第二笔报工。

### UC-026/027 FQC 与质量处置

1. 为工单创建 FQC 或返工复检。
2. 质检员提交通过/失败数量。
3. 全部通过时状态为 `PASSED`。
4. 有失败数量时进入 `DISPOSITION_PENDING`，不能完工。
5. 质量主管选择返工或报废；报废审批人与检验人分离。

### UC-028 完工入库

1. 预览按需求 pegging 的确定性销售分配。
2. 提交通过的 FQC、数量、仓库映射、追溯方式、批次/序列号和生产日期。
3. 服务校验可完工量和序列号唯一性，创建 `POSTING` 完工与异步任务。
4. WMS 回调 `UNKNOWN` 时保持 `POSTING`。
5. WMS 明确拒绝时进入 `FAILED`，修复后复用原库存幂等键重试。
6. WMS 返回 `POSTED` 和唯一流水后，更新完工、工单数量、销售分配和 Outbox。

### UC-029 工单结案

1. 系统检查未关闭 FQC、投退料和完工任务，以及入库数量事实。
2. 无阻断项时提交结案复核，工单进入 `CLOSING`。
3. 与提交人不同的账号执行复核。
4. 复核通过后工单进入 `CLOSED`，保存审计和事件。

## 6. 平台与权限异常用例

### UC-E01 无权限访问

- 触发：用户点击无权限按钮或通过 URL 直达页面/API。
- 期望：前端隐藏/禁用入口；后端仍返回 403；不返回目标数据；提供申请权限或联系管理员提示。
- 当前支持：旧版生产入口的需求池使用签名会话读取正式需求列表，正式生产 API 仍执行后端权限校验；其余旧版生产动作和其他业务域主要只有前端菜单过滤或本地原型。

### UC-E02 权限处理中被收回

- 触发：用户打开页面后角色、账号或工厂范围被停用。
- 期望：后续请求由服务端拒绝；页面清理敏感数据并回到工作台；记录权限版本和 Trace。
- 当前支持：签名令牌固定权限快照并记录权限版本，但没有服务端撤销或权限变更即时失效；需要令牌过期或重新登录后更新。

### UC-E03 并发版本冲突

- 触发：两名用户基于同一版本修改单据。
- 期望：仅首个提交成功；后一个收到明确冲突和刷新建议；不得静默覆盖。
- 当前支持：生产后端支持 `If-Match`；其他域未支持。

### UC-E04 重复提交

- 触发：重复点击、网络重试或客户端超时重发。
- 期望：同键同请求回放原结果；同键不同请求拒绝；不产生重复业务事实。
- 当前支持：生产后端支持；其他域未支持。

### UC-E05 外部系统结果未知

- 触发：WMS/MES/财务系统超时或连接中断。
- 期望：保持处理中，不创建第二笔事实；后台以原业务键查询或补偿；超时达到阈值后产生人工待办。
- 当前支持：生产完工库存状态支持；自动查询 Worker 和告警未实现。

## 7. 导入导出用例

### UC-090 批量导入

1. 用户下载当前版本模板。
2. 上传文件后系统校验文件类型、大小、列、字典、唯一性、权限和关联数据。
3. 返回总行数、成功候选数和错误行；存在错误时禁止确认入库。
4. 用户下载错误行并修复，重新上传。
5. 确认后异步写入，逐条记录结果和审计。

当前状态：未支持。

### UC-091 导出筛选结果

1. 用户设置筛选并点击导出。
2. 系统再次校验数据范围和导出权限。
3. 5000 行内直接生成；超过 5000 行创建异步任务。
4. 文件带租户、导出人、时间和可选水印，7 天后清理。
5. 系统记录筛选条件、行数、文件名和下载行为。

当前状态：未支持。

## 8. 用例验收通用规则

- 页面必须具备加载、空、错误、无权限、只读和成功状态。
- 写操作提交期间禁用重复点击；失败时保留用户输入。
- 业务错误说明“发生了什么、如何修复、是否可重试”，并返回 Trace ID。
- 所有列表受租户和数据范围过滤；导出使用相同过滤规则。
- 危险动作必须二次确认并记录原因。
- 业务数量和金额按契约精度处理，不使用二进制浮点数作为最终事实。
- AI 输出必须标识来源和辅助性质，不能绕过业务权限和审批。
- 自动化验收至少覆盖主成功路径、无权限、重复提交、并发冲突和外部结果未知。
