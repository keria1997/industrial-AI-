## 2. 已实施内容

### 2.1 公共请求与命令

- `ApiContext` 支持权限/范围版本，查询 scope 纳入这些版本；实际业务模块在身份、租户或授权变化时重新挂载，清除旧草稿和选择。
- 旧身份请求的 401 不再退出新会话；公开登录请求的 401 不会误清已有业务会话。
- JSON Content-Type 的 204 不再尝试解析空响应体。
- `useBusinessCommand` 冻结首次提交闭包和幂等键，未知结果重试复用原请求体/版本/键；支持直接重试原请求，防止重新校验新 props 阻断原请求恢复。
- 命令处理中防重复；换 scope/卸载后的返回不更新当前页面。保留结构化 ApiError 供业务页处理。
- 已接入销售复核/取消/快速开单、收付款确认、采购收货/执行、工作中心选择等调用点；这不是所有旧命令已完成改造的声明。

### 2.2 销售及售后读取

- RMA 贷项采用 `creditNoteFinanceId/creditNoteAmount`。
- 签收读取正式 `lines[]`，按来源行展示已发、签收、拒收及破损数量和单位，不跨单位加总。
- 快速开单读取实际负责人、工厂、授权仓库和客户资料；收货人、电话、国家、省、市、地址完整录入，移除虚构电话、上海地址和固定工厂兜底。
- 保留 PRD 已冻结的 CNY/税率默认；产品单位直接使用来源单位，不把件/台/个自行改成 PCS。
- 创建前校验并冻结实际命令输入，未知结果重试不会因日期跨日重新构造不同请求体。
- 发货弹窗通过稳定产品 ID 和实际授权仓库查询库存；缺少来源或无权限时不请求样例仓库、不按名称猜产品 ID、不显示本地库存兜底。
- 销售监控要求来源版本、数据时间和完整性声明；不完整数据不投影为零风险。零风险仍保留卡片标题/描述，隐藏建议。
- 发货、财务办理、客户签收、销售完成关闭的提示分开，流程导航不能代表完成事实。
- RMA、签收异常续办和销售关闭写入口仍按 B-03/B-05/B-06/B-07 保持阻断。

### 2.3 库存主数据

- 物料和产品复用授权仓库选择，统一标签“库存仓库”；提交服务端仓库 ID。
- 物料新建必须选择仓库；产品新建允许不关联；已有停用/不可访问关联可保留，新关联必须是可用授权仓库。
- 保存响应未确认关联时提示“已提交但关联未确认”并重新查询，不当作普通失败重新创建。
- 原有输入焦点稳定、数字可清空再输入的行为继续保留并回归。

### 2.4 工作台

- 请求增加显式业务日期；当前默认 Asia/Shanghai，可传时区；日期、时区和授权变更使分页失效。
- 定时刷新只查首屏，只有用户主动加载更多才携带 cursor。
- 动态按事件 ID 去重并排序，不再用 50 条截断丢弃新事件；拒绝未推进的历史游标。
- 首屏刷新替换历史结果，避免拼接不同快照；没有放宽原有 1.1 projection 掩盖后端结构不一致。
- 当前后端未提供可靠租户时区，不能据此声称多时区工作台已经完成。

### 2.5 生产与采购

- 在真实 `LegacyProductionManagement` 入口增加工作中心选择，按需求工厂和资源归属筛选；移除 FAC/WC 固定编码推断。
- 需求/工单读取完整分页，显式检测截断、重复页、总数变化和读取上限，避免把前 200 条当全集。
- 移除每 3 秒对多个全集轮询；保留初次、显式及窗口恢复可见时刷新。
- MRP 成功后重读需求，不再本地构造 status/version+1；成功但刷新失败分别提示。
- MRP 缺失在途和批量规则展示“未提供”，不再显示虚构 0/L4L 或自行拼凑净缺口公式。
- 完工入库缺少可靠来源字段时不再发送固定值；当前属于“阻断保护已修复、正常办理未完成”。
- 采购收货未知结果时保留原批次资料和键；重试不因新读取的余量改变而重写原请求。

### 2.6 财务

- 实际财务页新增“合并台账”“核销事实”，分别消费裸数组和分页契约；不自动新增核销，不串联确认后再次扣账。
- 台账展示接口每类最多 1000 条的范围限制，不以当前集合声称全盘汇总；核销按行展示。
- 支持 reversed/REVERSED 状态。
- 共享金额格式化使用十进制字符串/BigInt，保留超出安全整数的金额和合法红字。
- 当前 AR/AP、成本页面的金额投影不再先 parseFloat，AR/AP 按实际币种显示；缺币种明确标注。
- 财务看板聚合没有币种/换算/完整性来源，金额组件保留但显示 `-` 和口径待确认；不把混合来源总和显示为人民币万元。按来源确认的笔数和明细仍可展示。
- 作废、冲销、未知状态或不具备正余额的单据不开放新的收付款登记。
- 财务核销/冲销写办理和余额守恒验收仍依赖 B-03/B-04。

### 2.7 平台、认证、人员与其他

- 企业资料仅允许服务端支持的字段和版本提交；禁止混合命令和隐式管理员交接。已提交但 snapshot 刷新失败单独提示。
- 审计页改成服务端筛选/分页，使用 startTime/endTime；当前后端 total 是估算值，页面显示当前页及“总数待服务端确认”，不伪称准确总数。
- 员工账号请求携带租户上下文，状态修改保留 204；部门和岗位使用实际来源，临时口令仅在组件内存显示，切换身份后清除。
- 找回密码增加通用受理、链接解析、失效码反馈及成功后返回登录；输入口令不持久化。手机登录初始为空，切换号码清码；短信/验证码/登录防重复并处理迟到响应，不展示 devCode。
- 退出调用业务后端并清本机会话，撤销成功与结果未知分别提示。
- 菜单识别实际 finance.receivable/payable、hr.employee/skill、sc.supplier/customer/risk 等读权限；员工/技能、供应商/客户/风险各分区独立读取，不因一个分区失败清空其他数据。
- 人员考勤/排班及相关监控继续隐藏；员工档案保持展示与搜索。
- AI 导入只接受实际已实现的 UTF-8 CSV，空授权列表代表无可用类型；异步解析/列映射有身份与世代隔离，迟到建议不能覆盖人工修改。
- 物料导入补仓库必填、授权启用仓库校验；逐行保留幂等键，成功行不重复写，失败与结果待核实分开显示。
- AI 方案提交保留未知结果的原内容/键；审核 client 补版本；所有模型调用仍经业务后端，不新增浏览器推理逻辑。
- 消息来源解析支持 WorkOrder/ProductionDemand/PurchaseRequest/ShipmentTask 的正式别名。

## 5. 下一步实施门槛

1. 后端/产品按计划 B-01～B-12 提供明确解除证据，优先工作台结构与授权分页、财务余额/核销/冲销、售后状态与续办。不能依据 HTTP 200 或“已修复”口头结论直接开放办理。

本轮不修改任何 B 项对应的后端实现；保留工作区中不属于本轮的 artifacts 等文件。
