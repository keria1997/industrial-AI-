## 3. `TECH-DEC-002`：WMS Adapter 开发契约

### 3.1 权威边界

- WMS 仍是实物库存、预留和出入库流水权威源。
- 平台库存域拥有履约任务、WMS 调用状态、预留/出库投影、Inbox/Outbox 和补偿。
- 领域服务只依赖 `InventoryGateway` 端口，不依赖具体 WMS 厂商 DTO。
- 开发环境提供确定性的 `ReferenceWmsAdapter`；其结果必须明确标记 `REFERENCE`，不能作为客户 UAT 证据。

### 3.2 必须实现的端口

```ts
interface InventoryGateway {
  getAvailability(input: AvailabilityQuery): Promise<AvailabilityFact[]>;
  checkAndReserve(input: ReserveCommand): Promise<ReserveResult>;
  queryReservation(operationKey: string): Promise<ReserveResult>;
  releaseReservation(input: ReleaseCommand): Promise<ReleaseResult>;
  queryRelease(operationKey: string): Promise<ReleaseResult>;
  postSalesOutbound(input: OutboundCommand): Promise<OutboundResult>;
  querySalesOutbound(operationKey: string): Promise<OutboundResult>;
  postCompletionInbound(input: CompletionInboundCommand): Promise<InboundResult>;
  queryCompletionInbound(operationKey: string): Promise<InboundResult>;
}
```

所有写命令包含：`tenantId`、稳定 `operationKey`、`warehouseId`、业务来源 ID、来源版本、行数量、单位、`correlationId` 和 `traceId`。结果只能为：

- `SUCCEEDED`：返回唯一外部单据/流水 ID 和新事实版本。
- `PARTIALLY_SUCCEEDED`：仅在订单与行均允许分批时返回成功量和缺口。
- `SHORTAGE`：明确库存不足且没有产生超出规则的预留。
- `PROCESSING_UNKNOWN`：超时或结果未知，必须使用原键查询。
- `REJECTED`：明确拒绝，返回稳定错误码且没有未声明的业务事实。

### 3.3 并发与版本

- `checkAndReserve` 在 Adapter 边界表现为单次原子命令；禁止用“先查再普通写”伪装。
- 同一 `operationKey` 终身返回同一业务结果或其后续确定状态，不产生第二份预留/流水。
- `factVersion` 在租户+仓库+产品维度单调递增；陈旧版本不覆盖投影。
- 真实 WMS 若无法原生满足，由客户 Adapter 使用 WMS 可用锁、预留单或平台受控序列化实现，并在联调评审提供并发证据；无法实现时必须变更基线。

**结论：**关闭 `JR-P0-003`。真实端点、认证、限流、报文映射和 SLA 转为 `JR-P1-001~003`，阻断联调但不阻断领域开发。

## 4. `TECH-DEC-003`：正式身份与权限上下文

### 4.1 统一应用上下文

销售、库存和生产模块统一依赖可信 `AuthContext`：

```ts
type AuthContext = {
  accountId: string;
  employeeId?: string;
  tenantId: string;
  authorizedTenantIds: string[];
  permissions: Set<string>;
  permissionVersion: string;
  dataScopes: Array<{ type: string; ids: string[] }>;
  authMode: "development-hmac" | "oidc" | "service";
};
```

- Token 的租户、身份和权限声明是权威；请求头只选择已授权租户。
- 禁止生产模式接受 `X-Actor-Id`、`X-Permissions` 等自报身份或权限。
- 职责分离、数据范围和状态守卫全部在应用服务执行，前端隐藏按钮不是授权。
- 内部 Worker 使用可审计服务身份，并为每条消息显式设置事件租户。

### 4.2 模式决策

- `development-hmac`：复用现有签名令牌，仅开发/自动化测试允许；TTL 保持现有开发配置，不作为生产安全基线。
- `oidc`：客户环境目标模式，使用 OIDC Authorization Code + PKCE，服务端通过 issuer/audience/JWKS 验证访问令牌；生产启动时缺少配置必须失败。
- `service`：内部 Adapter/Worker 使用独立服务身份、最小权限和可轮换凭据，不复用用户令牌。
- 权限版本校验最长缓存 5 分钟；高风险补偿和权限管理动作必须实时校验。令牌撤销或权限中心不可用时写操作失败关闭。

实现使用 `AUTH_MODE` 显式选择模式；生产配置禁止 `development-hmac`。客户 IdP 地址、client ID 和声明映射属于联调配置。

**结论：**关闭 `JR-P0-004`。

## 5. `TECH-DEC-004`：敏感字段加密与密钥管理

### 5.1 加密信封

- 收货电话使用 AES-256-GCM 信封加密；每次加密使用随机 96 位 IV。
- `recipient_phone_ciphertext` 保存版本化密文信封，包含算法版本、IV、密文和认证标签；`recipient_phone_key_id` 单独保存非敏感密钥版本。
- AAD 至少包含 `tenantId + aggregateType + aggregateId + fieldName`，防止跨租户或跨字段替换。
- Outbox、Inbox、审计、错误和日志只保存密文或掩码；WMS Adapter 在最后调用边界按服务权限解密。

### 5.2 密钥提供者

```ts
interface KeyProvider {
  currentKey(tenantId: string): Promise<{ keyId: string; key: Uint8Array }>;
  keyById(tenantId: string, keyId: string): Promise<Uint8Array>;
}
```

- 开发环境使用 `LocalDevelopmentKeyProvider`，密钥来自 `DEV_DATA_ENCRYPTION_KEY`，不得提交仓库或用于 UAT。
- 生产环境使用客户批准的 KMS/Vault Adapter；应用数据库不保存主密钥。
- 轮换采用“新写新密钥、旧数据可读、后台幂等重加密”，保留审计但不记录明文。
- KMS 不可用时禁止创建或修改含敏感字段的单据，不降级明文。

**结论：**关闭 `JR-P0-005`。客户 KMS 厂商、密钥 ID 和恢复责任在 UAT 前配置。

## 6. `TECH-DEC-005`：数据库实施批准

### 6.1 批准范围

批准 `FULFILLMENT-DB-DESIGN-20260726-01` 作为开发基线，并按以下顺序生成：

1. `003_shared_fulfillment_infrastructure.sql`
2. `004_sales_fulfillment.sql`
3. `005_inventory_fulfillment.sql`
4. `006_production_fulfillment_link.sql`

迁移必须同时具备 PostgreSQL/PGlite 自动化测试，覆盖重复执行、约束、RLS、跨租户、升级和失败回滚。已产生业务事实后只允许前向修复，不通过 down 脚本删除事实。

### 6.2 数据库角色

| 角色 | 权限 |
| --- | --- |
| `app_migrator` | 对目标 Schema 执行迁移；不作为运行账号 |
| `app_runtime` | 销售/库存 API 所需最小 DML；无表所有权、无 `BYPASSRLS` |
| `app_worker` | Inbox/Outbox/补偿所需最小 DML；每次事务显式设置租户 |
| `app_readonly` | 经批准的只读查询；仍受 RLS 和脱敏视图约束 |

所有业务表 `ENABLE` 且 `FORCE ROW LEVEL SECURITY`，复合租户外键防止跨租户关联；运行时 SQL 仍显式过滤 `tenant_id`。

### 6.3 开发容量和保留默认值

以下用于索引和测试，不替代客户最终容量确认：

| 项目 | 开发设计值 |
| --- | --- |
| 活跃租户 | 1~10 |
| 每租户年销售订单 | 100,000 |
| 每订单最大行数 | 200，常态不超过 20 |
| 年库存事实/事件 | 每租户 10,000,000 |
| 业务订单、审批、出库、补偿、审计 | 默认 7 年，客户政策可延长 |
| 已处理 Inbox/Outbox 完整载荷 | 在线 180 天，随后加密归档；去重键至少保留 2 年 |
| 普通幂等记录 | 30 天；库存外部写入结果定位至少 2 年 |
| 死信和人工补偿 | 关闭后 7 年 |

库存事件达到单表 50,000,000 行或索引/清理 SLA 不满足时，按月分区；首个迁移不提前引入无数据依据的分区复杂度。客户最终容量、RPO/RTO 和保留要求仍须在 UAT 前复核。

**结论：**关闭 `JR-P0-006`，允许 DBA 迁移实现进入开发；客户生产 DBA 仍需在上线评审复核容量、账号和备份配置。
