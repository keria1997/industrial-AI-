# 销售发货弹窗回归

日期：2026-10-13。用户要求：销售订单点击“去发货”只展示弹窗，由用户手动进入出库管理；未经用户明确变更不得恢复自动跳转。

权限增量验收（2026-10-13）：成功弹窗的“进入出库管理”同时受库存模块访问权限及 `inventory.shipment-task.read`（或 `*`）控制，导航处理使用相同判断。缺少任一权限时隐藏按钮，销售发货申请及弹窗关闭仍可用。

TypeScript、24 个文件的 117 项前端测试、生产构建通过。扩展 `scripts/verify-sales-outbound-dialog.mjs` 后，在 1280×720 和 1920×1080 下分别验证了无库存模块访问权限、仅销售权限、具备出库任务读取权限三种会话的订单行、更多操作和详情入口；无权限按钮不存在，关闭和“我知道了”保持销售 URL，有权限入口保留。原有首次申请、失败和手动跳转回归也通过，无浏览器异常，未新增真实发货申请。

权限场景通过修改浏览器会话的角色及权限快照模拟，真实访问令牌保持原样，用于验证前端入口控制，不作为服务端撤销或鉴权的验收证据。手动导航断言按正式订单 UUID 验证。截图位于 `docs/tests/artifacts/sales-outbound-dialog-20261013/`，新增文件名以 `sales-only`、`no-inventory-module` 和 `inventory-task-reader` 开头。

实际修改：保留正式发货申请及订单刷新流程，删除申请成功后的自动导航；原有成功弹窗新增“进入出库管理”，点击后携带正式订单编号定位库存出库任务。“我知道了”和关闭按钮只关闭弹窗。进入出库管理的审计记录移至用户实际点击导航时写入。

验证环境：前端 `http://127.0.0.1:5175`，Java API `127.0.0.1:8081`，Chrome / Playwright。使用真实登录会话及已有已确认、已移交仓库订单 `SO-20261013-72D543F6`，未创建额外业务订单或发货任务。

`npm run typecheck`、`npm run test:frontend`（22 个文件，93 项测试）、`npm run build` 均通过。构建保留现有包体积及静态/动态混合导入提示。
