# 销售发货弹窗回归

日期：2026-10-13。用户要求：销售订单点击“去发货”只展示弹窗，由用户手动进入出库管理；未经用户明确变更不得恢复自动跳转。

实际修改：保留正式发货申请及订单刷新流程，删除申请成功后的自动导航；原有成功弹窗新增“进入出库管理”，点击后携带正式订单编号定位库存出库任务。“我知道了”和关闭按钮只关闭弹窗。进入出库管理的审计记录移至用户实际点击导航时写入。

验证环境：前端 `http://127.0.0.1:5175`，Java API `127.0.0.1:8081`，Chrome / Playwright。使用真实登录会话及已有已确认、已移交仓库订单 `SO-20261013-72D543F6`，未创建额外业务订单或发货任务。

| --- | --- |
| 1280×720：订单行“去发货” | 展示成功弹窗，销售 URL 不变；“我知道了”后保持销售页面 |
| 1280×720：更多操作“去发货” | 展示成功弹窗，销售 URL 不变；关闭后保持销售页面 |

| 浏览器异常 | 0 项 |

首次申请和失败场景只验证前端对 HTTP 响应的交互，不作为本次新增后端落库证据。已有任务恢复和手动进入出库管理使用真实后端。剩余发货沿用相同申请及成功弹窗流程，本次未准备真实部分发货样本。

`npm run typecheck`、`npm run test:frontend`（22 个文件，93 项测试）、`npm run build` 均通过。构建保留现有包体积及静态/动态混合导入提示。

回归脚本：`scripts/verify-sales-outbound-dialog.mjs`。安装 Playwright 的环境执行 `node scripts/verify-sales-outbound-dialog.mjs`；使用外部运行时时通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块入口。可通过 `SALES_UI_URL`、`SALES_TEST_ACCOUNT`、`SALES_TEST_PASSWORD` 覆盖测试地址和本地开发账号。脚本需要本地开发验证码及一张已有已确认、已申请发货订单。
