## 1. 结论及范围

保留 `LegacyProductionManagement` 入口和原有页签，已修复正式生产执行主链的阻断。使用同一张前端新建需求和同一张工单，实际走完：

本样本是手工生产需求，与修复前审计中的销售订单没有来源关联，不将两张单据拼接为同一销售订单全链路验收。销售移交、库存映射和出库的独立验收见当天销售及库存验收报告；本报告证明生产需求至采购补料、生产执行、入库和结案的连续链路。

## 2. 修复内容

| 原阻断 | 修复后行为 |
| --- | --- |
| 预置需求/FQC 列表可见，但命令 404 | 迁移和运行时统一租户复合键；JDBC 事务重读并加锁 |
| MRP 固定无缺料、BOM/工艺快照随机生成 | 服务端 BOM 快照与真实库存展算；多需求共享库存只净额计算一次 |
| 齐套只预检，无法保存 READY；下达可绕过预检 | 全行物料预留后保存 READY；下达执行相同阻断规则 |
| 已下达工单不能开工，恢复状态机错误 | RELEASED 开工、PAUSED 恢复；首次开工实际消费预留并记录物料出库 |
| 报工/FQC/入库只改本地状态 | 正式工单、实际数量报工及检验 API；库存 Worker 入账后才显示已入库 |
| NG 无返工复检闭环 | 返工完成自动生成复检，复检通过或报废后关闭原质量处置 |
| 完工误去重、失败可再建造成超量 | 各完工独立库存身份；重试沿用原任务，失败占用额度 |
| 报工不良品恢复后不能入库 | 质量恢复量单独累计，不改原报工历史，纳入入库上限 |
| 刷新丢 APS/工单进度、可能重复建单 | 服务端保留需求与 APS/工单关联；阻止重复建单及本地修改正式聚合 |
| 关单无实际入口 | 数量及开放事项检查，制单/复核必须不同账号，最终 CLOSED |

## 4. 详细前端操作

以下是本次已执行的步骤。再次验收时应新建需求，新编号由系统生成；保留已有已结案样本用于查看，不能重复对它报工或入库。

1. 打开 5175，选择账号登录，使用 `test01` 和当前验证码登录；确认租户为上海万申工业集团。
2. 进入“生产管理 → 主计划(MPS)”，打开“常规计划”。需求来源选择普通生产，来源描述填写验收说明；生产目标物料选择 FG001，计划数量填 5，交期日期填 2026-10-20，点击“确认保存”。当前表单默认工厂 FAC-SH-01、成品入库仓 WH-FG-01，没有工厂/仓库选择控件。正式创建需求返回 201；本次生成 DM-37123。
3. 在新需求行悬停行末图标，点击“需求校验”，状态进入待审批。服务端确认 BOM 存在并有关联工艺快照。
4. 在独立浏览器会话登录 `reviewer`，进入同一租户和 MPS 页，定位需求，点击“异人审批”。
5. 返回 `test01`，刷新，等待正式需求列表加载。点击“计划员接收需求”，再点击“接收后推送 MRP 展算”。
6. 查看“运算控制台”对应需求的缺料。本次实际缺口：RM201 10.5、RM202 5.1、RM305 5。缺料时不能直接 APS 或下达。
7. 对各缺料行点击转采购申请，形成下表三张 PR。进入“采购管理”，由 `reviewer` 审批生成 PO，再登记每笔实际到货并入库。三笔收货 API 均返回 201；不能只创建 PO 就认定补料完成。
8. 回“生产管理 → 主计划(MPS)”，运行 APS，再点击“基于成功排程创建工单”。服务端保存候选及工单关联；本次创建 WO-MV6PS1EF0899。
9. 在“订单与齐套”定位工单，点击“齐套检查”。实际预留三项 BOM 物料，显示齐套；然后点击下达。缺料或库存事实缺失会阻断，不允许强行下达。
10. 进入“车间与物流”，定位 `JOB-WO-MV6PS1EF0899`，点击“开工”。正式工单进入 IN_PROGRESS，后台消费物料预留并记出库流水。
11. 点击“登记报工”，本次输入良品 5、不良品 0、报废 0、新增投入 0，提交。计划量和已有投入均为 5；不得重复增加已投入量。正式报工返回 201。
12. 点击送 FQC，送检 5 PCS。进入“质量与结案”，定位 FQC-MV6QFR1T4C71，点击“录入检验”，填合格 4、不合格 1，提交检验结果。状态为待质量处置，暂不能入库。
13. 点击“生成返工单”，覆盖全部 1 件不合格量；完成实物返工后点击“返工完成送复检”。产生独立子检验 FQC-MV6QHXPFA388，送检 1。
14. 对子检验点击“录入检验”，填写合格 1、不合格 0并提交。子检验 PASSED，原检验 REWORKED；NG 处置完成。
15. 分别点击原检验和子检验的“确认成品入库”，数量分别 4 和 1。页面先为入库处理中，后台完成后自动显示已入库及独立库存流水。HTTP 202 只是提交成功，必须等待 POSTED。
16. 进入“库存管理 → 仓库 → 成品主仓 → 库存内容”。FG001 现有总量 5 PCS、冻结/预留 0、实际可用 5；本次没有与其他来源库存混为同一完工数量。
17. 回“生产管理 → 质量与结案”，工单显示已完工，点击“提交结案”。结案检查 canClose=true、blockers=[]。
18. 同一 `test01` 点击“复核结案”实际被 403 拒绝，符合异人规则。由独立 `reviewer` 会话点击“复核结案”，返回 200，工单 CLOSED。
19. 刷新页面，检查工单、两个 FQC、两笔完工和已结案状态仍在。最终部署后再次刷新核对同一批单据。
