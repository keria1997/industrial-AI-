## 1. 结论及范围

两类订单均通过实际前端点击、正式 Java API 和 PostgreSQL 持久化完成闭环，没有直接修改数据库、注入库存或伪造业务响应。

- 普通生产：新建 2 PCS → 本人校验/审批 → 接收 → MRP/三项采购补料 → APS → 工单齐套预留/下达 → 开工扣料 → 报工/FQC → 2 PCS 成品入库 → 复核结案。
- 销售缺货：同一销售订单 9 PCS、仓库可用 6 PCS → 原任务预留/申请缺口 3 PCS → 本人审批 → MRP/采购补料 → 生产/FQC/入库/结案 → 原任务重检 → 全量发货 9 PCS → 原销售单 SHIPPED、剩余 0。
- 最终部署重启后重新读取：两工单 CLOSED、两成品入库 POSTED、原任务 COMPLETED、销售 SHIPPED、库存现存/预留/可用均为 0。

本结论覆盖上述两条履约链路。APS 使用 Reference 候选，客户真实 MES/WMS、完整有限产能求解、BOM/工艺/设备维护导入、委外和财务全链路仍须独立开发或验收，不据此宣布整个生产模块全部完成。
