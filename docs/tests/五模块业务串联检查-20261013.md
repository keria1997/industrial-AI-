检查日期：2026-10-13，Asia/Shanghai。范围：当前未提交工作区的 React 主入口及 Java 后端。

## 1. 结论

**五个模块尚未完全打通，当前是部分接口和局部业务串联。**

销售订单到仓库任务、已有采购订单到库存入库、已有应收应付到财务结算具备可执行实现。但不能连续完成同一来源上的：

`销售订单 → 库存缺货 → 生产需求 → MRP 缺料 → PR/PO → 采购入库 → 齐套/领料 → 工单开工/报工 → FQC → 完工入库 → 原任务发货 → 应收/应付 → 结算及业务关闭`

本报告不把页面跳转、成功提示、预置单据或隔离测试数据算作业务打通，不沿用历史 TypeScript 后端的闭环验收结论。

| 链路 | 判定 | 实际能力与断点 |
| --- | --- | --- |
| 销售创建 → 复核 → 确认 → 仓库任务 | 局部串联 | 有正式 API、版本控制和来源；控制器测试覆盖 |
| 库存预留/出库 → 销售部分/全部发货 | 局部串联 | 更新库存事实、任务、订单数量及状态；仍为 Reference 库存适配 |

| 需求审批/接收 → MRP/APS | 接口可推进，计算不完整 | MRP 固定无缺料；APS 不检查物料且只生成当前时间候选 |
| MRP 缺料 → PR → PO | 断开 | PR 依赖缺料行，当前实际 MRP 不产生缺料 |
| 已有 PO → 收货/验收/退货 → 库存 | 局部串联 | Java 已有入库事实、待检/验收、退货代码；上游 MRP 未连通 |

| 完工事件 → 库存增加 → 原任务重校验 | 存在漏账 | 信封字段丢失；两笔各 10 件完工仅增加 10 件库存 |
| 销售出库 → 应收 | 断开 | 有出库事件，未实现财务消费及来源应收创建 |
| 采购入库/退货 → 应付/冲销 | 断开 | 有库存事件，没有应付生成及退货财务调整 |
| 已有 AR/AP → 收付款/发票/凭证 | 局部串联 | 有独立结算接口和持久化；不代表外部支付/开票/财务系统已联调 |
| 生产领料/工时/报废 → 成本核算 | 断开 | 成本接口接收手工金额，没有聚合业务事实 |

| 跨模块主数据及库存口径 | 部分接入 | 仓库页面已接 API；产品/物料维护、本地库存展示仍未统一 |

## 4. 高优先级问题

以下 P1 均影响主业务链正确性或可执行性。

### F01 [P1] 第二笔完工入库被静默误去重

代码：`ProductionService.java:652`、`ProductionFulfillmentOutboxWorker.java:66`、`FulfillmentService.java:578`。

生产真实事件把 `eventId`、`correlationId` 放在外层，载荷没有 `eventId` 和 `occurredAt`。Worker 只传 `payload`，库存却从载荷读取这些字段，用空事件编号做 Inbox 去重。

隔离复现：两个独立完工各 10 PCS、不同外部流水；Worker 返回 `published=2, failed=0`，最终库存只有 10 PCS、库存流水只有 1 条，`sourceEventId` 和 `asOf` 均为空。

影响：生产显示已完工/事件已发布，库存漏记，原发货任务可能持续缺货。应传递完整事件信封并校验编号/时间。现有 Worker 测试手工给载荷补了真实生产代码未生成的字段，未暴露缺陷。

### F02 [P1] MRP 固定无缺料，不能正常驱动采购

代码：`ProductionService.java:785`、`FulfillmentService.java:1452`。

MRP 直接设置 `canProceedToAps=true`、空 `materialShortages`，不读取 BOM 或物料库存；PR 却要求 MRP 有对应正数缺口。

隔离复现：没有任何物料事实，对 FG001 的 10 PCS 需求运行 MRP，仍返回无缺料；据此创建 RM201 PR 返回 424“MRP 任务没有对应采购缺口”。APS 仍可成功。

采购测试注入人工缺料结果，只证明采购子流程；不能证明实际 MRP 到采购打通。

### F03 [P1] 齐套不生成，实际下达又绕过预检

代码：`ProductionService.java:279`、`:335`、`:952`；`src/App.tsx:6507`。

创建工单不计算/保存 `kittingStatus` 或创建预占；页面“齐套检查”只调用下达预览。新工单不满足 `READY`，但正式下达未调用相同阻断检查。

隔离复现：预检 `canRelease=false/KITTING_NOT_READY`，直接下达仍成功进入 `RELEASED`。服务层也接受不存在的 BOM/工艺/排程引用；探针直接测试服务层，不把任意格式引用案例等同于 HTTP 格式校验结果。

应实现服务端齐套与预占，并在下达事务中重读校验；不能依赖用户先点击预检。

### F04 [P1] 工单开工/恢复状态机错误

代码：`ProductionService.java:350`、`:359`、`:1014`；`src/App.tsx:6592`。

`changeWorkOrder` 除暂停外，把目标状态当允许的前置状态：开工只接受 `IN_PROGRESS`，拒绝 `RELEASED`；恢复同样拒绝 `PAUSED`。

隔离复现：已下达工单开工返回 409“工单当前状态 RELEASED 不允许此操作”。恢复缺陷经同一分支静态确认，本次未单独运行恢复探针。

前端车间开工只改本地任务状态，没有调用正式开工；后续 API 报工要求工单 `IN_PROGRESS`，不能正常推进。

### F05 [P1] 多产品缺货申请冲突并留下未关联需求

代码：`FulfillmentService.java:872`、`:911`；`FulfillmentStoreConfig.java:40`；`ProductionService.java:847`。

多行缺货循环使用相同上下文和幂等键创建需求，第二行因内容不同被拒绝。履约和生产 JDBC 仓储各自管理连接与事务，没有共同原子事务。

隔离复现：真实服务创建两行订单、复核、确认、发货申请、缺货校验；提交两行生产申请返回 `409 PRODUCTION_409_IDEMPOTENCY_CONFLICT`，生产仓储已留下 1 条需求。没有在真实数据库重跑此案例；跨仓储事务风险来自代码检查。

每个来源行需要稳定独立幂等键，并实现跨域失败恢复或补偿。

### F06 [P1] 出库/收货没有生成财务 AR/AP

代码：`FulfillmentService.java:1113`、`:1635`、`:452`；`finance/FinanceOutboxWorker.java:46`；`src/App.tsx:13080`。

上游写出库/采购入库事件，但履约 drain 只处理销售发货申请，其余也被标成已发布。财务 Worker 仅标记财务自身事件已发布，不消费出库/收货事件。

全源代码检查未找到从业务来源新建 AR/AP 的消费实现；业务中的 `saveReceivable/savePayable` 更新既有单据。前端“生成财务单据”实际上查询已有 AR/AP，找不到就报错。

应实现按实际发货/收货确权、来源幂等、部分发货/分批入库以及退货调整，并保留单据及行关系。

### F07 [P1] 采购入库未接通生产库存/齐套

代码：`FulfillmentService.java:1597`、`:1635`；`FulfillmentStoreConfig.java:28`；`ProductionService.java:785`。

收货保存履约库存与流水，但配置只把生产任务读取和需求创建接给履约，没有反向同步生产物料或齐套的回调；生产计划也不读履约物料库存。

采购收货成功不能证明生产可开工。“采购入库解除生产齐套阻断”与当前实现不符，需要统一物料事实源、齐套重算、预占及领退料正式流水。

### F08 [P1] 报工、FQC、完工页面与后端事实不一致

代码：`src/App.tsx:6596`、`:6665`、`:6704`；`src/api/production/operations.ts:93`、`:102`。

- 正式报工失败后仍继续本地数量/质量任务更新；成功也未采用返回的新工单版本。API 报全部良品，页面一次 12 件却固定拆为 10 良品/2 不良。
- FQC 表单有 NG/返工/报废输入，正式调用却固定全部合格；随后页面又保存用户输入的另一组数量。
- 完工提交只返回 `POSTING`，页面已标记质量“已结案”、工单“已完工”，未等库存确认和独立结案复核。
- 领料任务由 `localStorage` 桥创建，不是服务端物料扣减或成本事实。

应停止失败后的本地推进，采用正式结果及版本，并按权威状态恢复页面。

### F09 [P1] 来源仓库没有写入工单快照

代码：`ProductionService.java:295`、`:311`；`src/App.tsx:6315`、`:6714`。

先保存空 `parameterSnapshot.inventoryWarehouseId`，后读取来源仓库时只修改输入，没有回填快照。前端创建工单不显式传仓库；完工时会退回默认 `RES-WH-FG-SH`。

隔离复现：来源仓库 `WH-SELECTED`，创建的工单参数仓库仍为空。成品可能投影到默认仓，而原任务按实际选仓匹配，不能唤醒原出库任务。

### F10 [P1] 主数据和库存显示仍有多个事实源

代码：`src/App.tsx:3666`、`:6911`、`:7621`；`features/inventory/pages/InventoryMasterDataPanel.tsx:330`、`:371`。

库存总览和销售可用量仍来自静态 `inv_stockData`；正式出库弹窗另读后端库存。销售可显示 FG001 可用 2300，选定仓库却为零/无记录。仓库维护已接 API，但产品/物料保存仍是本地集合。

需要统一正式库存查询、稳定仓库 ID、产品/物料、计量单位、价格税率和生效 BOM/工艺引用。

### F11 [P1] 预置单据加载键与查询键不一致

代码：`db/migrations/022_business_seed.sql:108`、`storage/JdbcJsonCollections.java:63`、`production/ProductionStore.java` 按 ID 查询。

种子 doc_id 为 `demand-seed-002/fqc-seed-001`；加载 Map 直接安装 doc_id，生产单条命令却用 `tenantId:id`。列表可见而操作找不到，与当天较早前端实测的 404 一致。

本次代码确认仍存在，没有数据库复测。应统一键规则并补已有数据恢复验证。

## 5. 其他缺口及已实现能力

- [P2] 财务结算没有回写销售业务完成的消费者；前端流程到 `settlement` 不等于订单聚合完成。
- [P2] `FinanceController.java:536` 接收手工成本，没有聚合领退料、工时、报废和采购价格。
- [P2] 采购页面审批不传价格税率，客户端固定供应商，Java 默认单价/税率为 0；页面路径不能保证后续应付金额正确。
- [P2] 库存低水位 PR、产品补货 MPS、部分调拨/盘点页面动作仍为本地流程。

应保留局部能力的正确描述：正式销售履约、预留/出库及销售回写存在；Java 采购已有供应商、部分收货、质检、退货代码；Java 财务已有查询、收付款、发票、凭证、成本、结算及 JDBC 仓储。不能笼统说这些模块“没有后端”。

当前 Reference 预留已把缺库存记录处理为 `SHORTAGE`，现有测试通过；当天较早报告中的 424 现象不能直接当当前代码结果。外部 ERP/MES/WMS、银行/税控/财务系统的真实同步及补偿本次没有验收证据。

## 6. 测试缺口

生产控制器仅测试就绪和需求到 MRP，未覆盖下达/开工/报工/FQC/完工/结案状态机；采购测试注入缺料；完工 Worker 测试注入字段完整的人工事件；财务测试预先保存应收单。前端 API/规则/路由测试也不等于浏览器连续验收。因此测试全部通过与上述断点同时成立。
