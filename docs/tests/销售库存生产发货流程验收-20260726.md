# 销售—库存—生产—发货前端流程验收报告

## 1. 验收结论

| 项目 | 结论 |
| --- | --- |
| 验收日期 | 2026-07-26 |
| 验收范围 | 销售订单待确认至全量发货的前端业务操作链路 |
| 需求依据 | V2.1.0 PRD 5.1、5.2、7.3.9.2、7.5.4~7.5.10；`docs/usecase.md` UC-012、UC-014、UC-100；`docs/task/task.md` TASK-DLV-005、TASK-DLV-007 |
| 测试方式 | 浏览器人工业务操作 + Playwright 语义定位与页面状态检查 + 现有自动化质量基线 |
| 总体结果 | **不通过** |
| 用例统计 | 12 项：5 项通过、4 项失败、3 项阻塞 |

当前前端只能走通“销售本地确认并移交仓库 → 仓库展示缺口 → 正式生产接入 API 创建需求 → 销售本地回写生产中”。正式需求虽能出现在生产需求池，但从 MPS 开始重新进入旧版本地原型，无法形成可追溯的工单、报工、FQC、完工入库和新库存事实；库存也没有可用的重新校验入口，因此不能恢复发货，更不能达到订单全量发货的验收终点。

## 4. 额外一致性检查

库存种子单 `OUT-260702-02` 显示来源 `SO-260615`、FG001 × 50；销售列表对应业务订单为 `SO-20260615-001`、FG001 × 1。点击该行“去发货”后，又打开了“库存不足，发起生产申请”弹窗，使用错误来源和 50 PCS 数量。该数据不能用于证明销售发货成功，并存在错误生产补货或错误出库风险。

## 5. 需求覆盖与退出条件

未满足的关键退出条件：

1. 待确认订单的复核/审批、发起发货、仓库校验三个动作及状态必须分离。
2. 正式生产需求必须继续驱动正式 MPS/MRP、工单、报工、FQC 和完工入库，不得以本地状态或 Toast 代替。
3. 完工库存事实必须关联原销售出库任务，并提供“重新校验”。
4. 必须验证部分发货、剩余发货和全量发货，最终销售订单达到 `SHIPPED`。
5. 销售订单、来源行、生产需求、工单、完工和出库结果应按同一 Correlation/Trace 可见追溯。

在 `docs/bugs/销售库存生产发货流程缺陷-20260726.md` 所列 P0/P1 缺陷修复并完成 QA 复验前，不建议再次执行同范围全链路验收。
