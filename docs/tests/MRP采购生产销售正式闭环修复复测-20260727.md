# MRP—采购—生产—销售正式闭环修复复测报告

## 1. 结论

- 复测日期：2026-07-27
- 目标链路：MRP -> PR -> 异人审批并生成 PO -> 采购入库 -> 物料齐套 -> 生产入库 -> 成品库存重校验 -> 销售出库
- 结论：Reference 正式闭环已形成，原报告中的 P0 断点已关闭。
- 边界：本结论只覆盖参考产品 `FG001`、外购物料 `RM201`、参考仓库与 PO 全量收货；不代表完整采购域、客户优化器或 ERP/SRM/WMS 已联调。

## 3. 自动化业务流

`server/test/fulfillment-api.test.ts` 的缺货主路径现在强制执行：

1. 销售订单复核并创建发货申请，库存检查得到成品缺口。
2. 创建并审批生产需求，运行 MRP 得到 `RM201` 缺料。
3. 在采购入库前执行 APS，断言服务端拒绝。
4. 从 MRP 缺料创建 PR，由不同账号审批并生成 PO。
5. PO 收货形成采购入库单、库存流水和物料可用量事实。
6. 重新运行 APS，创建工单；调用方即使提交 `SHORTAGE`，服务端仍按事实派生 `READY`。
7. 工单下达、开工、报工、FQC、生产完工和成品入库。
8. 原销售发货任务按新库存事实重新校验、预留并正式出库。
9. 断言销售订单最终进入 `SHIPPED`。

## 5. 剩余风险

- Reference BOM 只覆盖固定产品/物料，不支持多层 BOM、替代料、损耗、批量、在途和安全库存策略。
- 采购收货当前为 PO 全量收货，不支持部分收货、超欠收、退货、来料质检和批次/序列追踪。
- 供应商、价格、合同和税务仍为页面原型；ERP/SRM/WMS 与消息代理尚未进行客户联调。
- 页面业务流引导状态仍在 React 中，但 PR、PO、收货、库存、工单、完工和销售出库的成功事实均以 API 为准。
