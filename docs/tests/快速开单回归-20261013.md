# 快速开单回归

用户需求：快速开单与新增报价单使用相同页面内容，创建成功后进入销售订单待发货。

实现：两个入口使用同一个表单，包含客户、报价日期、有效至、仓库、多产品明细、优惠和备注。快速开单直接创建正式销售订单，不生成报价单；完整传递所有产品行、单位、数量、单价、折扣和优惠后总额。成功后关闭弹窗并选中待发货，清除旧搜索和客户筛选。提交中禁止重复点击和关闭，失败保留输入，未改内容的重试复用幂等键。

边界：正式订单目前使用一个发货仓库，混仓提交会明确提示；不会偷偷选择默认仓库或替换产品。有效期与最终承诺交期分别处理，交期在后续确认订单时固化。日期/有效期/备注及产品名称规格已补齐 Java/JDBC 持久化，读取以服务端字段为准；历史工作区快照仅保留兼容。正式订单数量、价格、金额与状态以 API 为准。

自动化：新增 `quickSalesOrder.test.ts`，覆盖多产品、单位、仓库解析、折扣金额、客户及数量校验、接口失败和稳定幂等键，以及有效期不作为交期。

浏览器脚本：`scripts/verify-quick-sales-order.mjs`，使用本地 `5175` 前端、`8081` Java API、真实开发账号及 Chrome。权限失败使用 HTTP 403 桩，随后恢复真实创建接口；成功创建订单用于页面及刷新验证，没有发起审批、确认或发货。

1280×720 和 1920×1080 均验证：

- 新建报价单与快速开单的字段标签、表格列、输入类型和备注结构一致。
- 缺客户、缺产品的校验生效，修改后清除旧错误。
- 两个产品行分别提交数量 2 和 3、单价 120 和 80，90% 折扣减 12 元，服务端优惠后金额为 420 元。
- 创建失败保留两行产品及备注，恢复接口后的重试使用相同幂等键。
- 返回 `PENDING_CONFIRMATION` 和 `NOT_REQUESTED`，列表自动选中待发货并清除旧搜索。
- 订单详情与刷新后的状态、产品行和备注保留，报价数量不增加，没有发货申请请求和浏览器异常。
