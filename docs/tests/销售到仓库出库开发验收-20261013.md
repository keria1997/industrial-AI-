# 销售订单到仓库出库开发验收

验收日期：2026-10-13。范围：销售订单确认、发货申请、仓库任务、库存预留、部分/剩余出库以及回写销售。Java/JDBC 真实业务实现、隔离 PostgreSQL 和真实浏览器均已验证通过。

## 1. 已实现行为

1. 销售复核/审批后确认发货内容，订单进入 `CONFIRMED`，不创建仓库任务。
2. “去发货”读取最新订单版本，按“剩余量 - 活动申请占用”申请发货；已有活动申请可恢复。成功后只展示销售发货弹窗，关闭或“我知道了”保持销售页面；只有“进入出库管理”导航，使用正式订单 UUID 定位。
3. 仓库读取权威库存，按任务行关联预留。前端展示“本任务未消费预留 + 新可用库存”，相同产品的多行只分配一次自由库存。
4. 首次预留完成后使用返回的新出库单直接过账；部分发货后补足原预留，保留出库单/行 ID 和累计已发量。
5. 出库校验正数量、非空/唯一行、单位、来源快照、预留上限、时间及禁止分批规则。已完全消费行不再提交。
6. 出库、不可变库存流水、库存事实、预留消费、任务、申请、销售累计量与状态、审计/历史、Outbox 和幂等结果同事务保存。成功返回权威 `task`、`order`；前端不依赖本地桥接制造正式发货结果。
7. 部分发货后仍为 `PARTIALLY_SHIPPED`；全量完成为 `SHIPPED`，活动申请占用和未消费预留归零。返回销售或刷新读取持久化事实。
8. 网络中断后复用请求键、时间、版本和完整数量包；结果未知不提示发货成功。Reference WMS 命令结果按租户持久化。
9. JDBC 租户事务获取 PostgreSQL advisory transaction lock 后重读事实，避免多个服务实例重复预留；失败回滚数据库并恢复缓存。正式订单、任务、出库及库存读取刷新数据库事实。
10. `FulfillmentOutboxWorker` 自动重试仓库移交；任务、Inbox、审计/历史和已消费标记原子写入。不支持的 Outbox 事件保持 `PENDING`，不误报外部发布成功。

| 场景 | 已验证结果 |
| --- | --- |
| 小数部分出库、服务仓储重建、原请求重放、剩余出库 | 数量 `0.1 + 0.2 = 0.3`；重放不重复流水；重新加载后仍为已发货 |

## 5. 验收边界

- 实际出库使用当前 Reference WMS Adapter，客户 WMS 的认证、映射、外部失败补偿和上线 SLA 尚未联调。
- 浏览器补货通过隔离环境新版库存事实准备；未把 MRP、采购、生产完工、财务连续链路计为通过。生产入口继续保持 `LegacyProductionManagement`。
- 客户报价、客户经营、财务应收来源事件及完整五模块闭环不在本次完成结论内。
- 本次修复阻止新的错误累计和重复扣减，未自动重写历史损坏业务数量；历史数据修复仍需独立核对来源流水。
- 租户事务锁优先保证库存与订单一致性，当前对同一租户的写入进行串行化；大规模性能验收未开展。
