# 库存事实统一验收

日期：2026-10-13。范围：仓库详情、现存量、发货校验、预留和实际销售出库的库存事实及仓库 ID 映射。

原问题：仓库详情从前端预置库存显示 FG003 的 150/30/120，发货从 Java 库存事实读取；仓库详情使用编码，后端主数据可能使用 UUID，两处既没有共同数量来源，也没有完整的仓库标识解析。

当前实现：

- `useFormalInventory.ts` 从正式仓库、产品/物料主数据和 availability 读取库存，供详情及现存量共用；不回退前端预置数量。
- 服务端 availability 查询接受可选仓库/产品筛选，省略筛选只返回当前授权租户事实。编码和服务端 ID 统一解析，响应返回服务端仓库 ID。
- 预留、扣减、库存事件和完工入库共用仓库解析；旧编码库存下一次有效更新时事务迁移到 ID 键，不复制库存。两个标识存在重复产品事实时返回 409，不相加或任意选择。
- 展示现存量、预留加冻结、可履约量及事实安全库存；在途不计可用量。发货额外计入本任务未消费预留，二者数量差异有明确业务口径。
- 缺事实显示 `-` 和“未查询到库存记录”，明确零库存显示 0；加载/错误时不显示可用量，支持重试。防止旧请求覆盖新请求及跨租户响应回写。
- 发货、主数据变化及窗口获得焦点时重读。正式库存不使用只改组件状态的编辑、删除、快速盘点入口。
- 迁移 028 补齐历史数据库库存组成，优先已有新版数量，重算安全库存扣减公式并递增事实版本；不导入前端库存。
