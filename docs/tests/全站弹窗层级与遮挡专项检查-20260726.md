# 全站弹窗层级与遮挡专项检查报告

## 1. 检查结论

- 检查日期：2026-07-26
- 检查环境：`http://127.0.0.1:4174/`
- 重点视口：1280 x 720
- 检查方法：全量静态扫描 `fixed`、`z-index`、滚动容器与悬停菜单，并对生产、销售、库存的代表性弹窗进行浏览器几何和截图验证。
- 总体结论：截图问题已稳定复现，属于生产模块的系统性弹窗层级缺陷，不是单个 MPS 弹窗的偶发现象。

## 2. 问题分类

### UI-LAYER-001 生产弹窗被模块导航覆盖

- 严重级别：P1 / 高
- 状态：失败
- 类型：层叠上下文错误、视觉遮挡、交互穿透
- 影响：弹窗标题、关闭按钮和表单内容可能被生产导航遮住；遮挡区的导航仍处于最上层并可接收交互，可能导致用户误切换页面。

复现结果：

1. 进入“生产管理 -> 订单与齐套”。
2. 点击第一条工单的“查看工单”。
3. 在 1280 x 720 下，生产导航覆盖弹窗上部。
4. 几何检查显示：弹窗遮罩覆盖全视口且自身为 `z-50`；生产头部为 `z-20`，导航为 `z-50`；但弹窗位于 `z-10` 的生产内容父层中，因此无法越过兄弟头部的 `z-20` 层叠上下文。

根因代码：

- `src/App.tsx:5246`：生产头部容器 `relative z-20`。
- `src/App.tsx:5257`：生产导航 `relative z-50`。
- `src/App.tsx:5294`：生产内容容器 `relative z-10`。
- `src/App.tsx:3397` 起：生产弹窗在内容容器内部使用 `fixed ... z-50`。

CSS 层叠规则决定子元素不能越过父级层叠上下文。因而仅把弹窗自身从 `z-50` 调高，并不能可靠解决此问题。

## 3. 全量影响范围

生产模块下列 9 类弹窗均渲染在 `z-10` 内容父层内，确认共享同一根因：

| 弹窗组件 | 业务入口 | 结果 |
| --- | --- | --- |
| `Prod_RecordModal` | MPS 查看/编辑、工单查看/编辑 | 失败，已动态复现 |
| `Prod_MpsModal` | 制定主生产计划、紧急插单 | 失败，同层级结构 |
| `Prod_PeggingModal` | MRP 供需溯源 | 失败，同层级结构 |
| `Prod_QcModal` | 质量检验结果录入 | 失败，同层级结构 |
| `Prod_EqModal` | 设备新增/编辑 | 失败，同层级结构 |
| `Prod_BomModal` | BOM 新增/编辑 | 失败，已动态复现 |
| `Prod_ImportBomModal` | BOM Excel/CSV 导入 | 失败，同层级结构 |
| `Prod_RouteHeaderModal` | 工艺路线新增/编辑 | 失败，同层级结构 |

生产模块还复用了 `Sales_ConfirmModal` 处理 MPS、工单、设备删除确认。这 3 个确认入口同样位于生产内容父层中，也会被生产导航覆盖。

合计至少涉及 9 类业务弹窗、3 类删除确认、18 个以上用户操作入口。

## 4. 关联问题

### UI-RESP-002 部分生产弹窗缺少统一短屏保护

- 严重级别：P1 / 高
- 状态：部分通过
- 类型：响应式、内容裁切风险

生产弹窗未统一采用“面板最大高度 + 内容区滚动 + 固定头尾”的结构。`Prod_QcModal`、`Prod_BomModal` 已有内容区高度限制；`Prod_RecordModal`、`Prod_MpsModal`、`Prod_PeggingModal`、`Prod_EqModal`、`Prod_RouteHeaderModal`、`Prod_RouteOpModal` 等仍依赖内容自然高度。当前种子数据下部分弹窗可显示，但字段增加、浏览器缩放或更矮视口时存在底部按钮/字段不可达风险。

### UI-A11Y-003 生产下拉菜单仅支持鼠标悬停

- 严重级别：P2 / 中
- 状态：失败
- 类型：键盘可访问性

“主计划(MPS)”和“基础主数据”的子菜单使用 `hidden group-hover:block`，没有键盘焦点展开状态、`aria-expanded` 或菜单键盘交互。键盘用户无法稳定访问“主生产计划”“工艺路线”“设备机台”等子页面。

## 6. 为什么此前没有测出

1. 原业务流测试重点覆盖状态变化、按钮可用性和跨模块数据流，没有建立“所有弹窗入口 x 视口尺寸”的视觉测试矩阵。
2. 既有页面检查主要观察页面级文字重叠，没有在弹窗打开后读取实际顶层元素和层叠上下文。
3. 只检查弹窗自身的 `z-50` 容易产生误判；真正的问题位于其父级 `z-10`，普通 DOM/功能断言不会失败。
4. 生产下拉菜单仅悬停可见，使部分 MPS、工艺路线和设备弹窗入口不容易被键盘或语义自动化遍历。

这是测试用例覆盖缺口，应补入回归门禁，不能归因于用户操作或偶发渲染。

## 7. 修复与验收建议

1. 将所有全屏弹窗统一渲染到应用根节点的 Portal/Overlay Host，避免受业务页面父级层叠上下文限制。
2. 定义统一层级令牌，例如页面、粘性表头、模块导航、下拉菜单、遮罩、弹窗、Toast，禁止页面内散落竞争性的 `z-index`。
3. 弹窗统一采用 `max-height`、内容区 `overflow-y-auto`、固定标题栏和操作栏。
4. 下拉菜单改为受控展开，同时支持鼠标、点击、Tab、Enter/Space、Escape，并补齐 `aria-expanded`。
5. 新增自动化门禁：在 1280 x 720 与 1920 x 1080 下逐个打开生产弹窗，断言遮罩为导航点位的最上层元素、弹窗矩形在视口内、操作栏可见可点击。
6. 修复后至少回归本报告列出的 18 个入口，并复测销售、库存、平台代表性弹窗，防止统一层级调整引入反向覆盖。
