# 生产模块前端操作与实测

日期：2026-10-13。范围：当前 Java 后端和用户批准的 `LegacyProductionManagement` 主入口。

## 1. 实测结论

当前前端不能完成真实的“销售缺货 → 生产 → 完工入库 → 发货”闭环。

- 实际成功：销售开单、异人复核、确认订单、移交仓库；独立验收需求的校验、异人审批、接收、MRP、APS、创建工单。
- 实际阻断：仓库缺货申请前的预留返回 424；预置需求校验和预置 FQC 提交返回 404；新工单的齐套预检不通过。
- 原型演示：全局 MRP 按钮、预置车间报工、预置 FQC 和成品入库均可以显示成功，但本次点击没有业务 API 请求。
- 未完成验证：同一张真实工单的下达、领料、开工、报工、FQC、WMS 入账、结案和销售最终发货。没有绕过齐套阻断来伪造全流程通过。

此前“已有测试覆盖需求到最终入库主链”的说法不准确。Java 生产控制器现有测试只覆盖就绪查询和需求创建、重放、校验、异人审批、认领、MRP。上一轮 Java 测试统计为 55 个，0 失败、0 错误、1 跳过，并非 55 个均执行通过。真实 JDBC smoke 测试未在上一轮得到完整验证。

## 3. 从销售进入生产：实际操作

### A1. 登录和开单

1. 打开前端，选择“账号登录”。
2. 输入 `test01`、密码和当次验证码，点击“立即登录”。
3. 确认顶部租户为“上海万申工业集团”。
4. 左侧进入“销售管理”，点击“快速开单”。
5. 客户填写“生产流程验收-20261013”。
6. 订单日期填 `2026-10-13`，交期填 `2026-10-20`。
7. 点击“添加产品”，产品填写 `FG001 生产流程验收`，数量 `1000`，单价 `1`。
8. 备注填“本地前端验收，检查需求到工单链路”，点击“创建订单”。

实际结果：销售 API 返回 201，生成 `SO-20261013-2DD0B2AD`，进入销售订单列表，状态“待发货”，复核状态“待复核”。

### A2. 异人复核、确认和移交

1. 用另一个浏览器会话登录 `reviewer`。
2. 进入“销售管理 → 销售订单”，定位上述订单。
3. 点击该行“更多操作”，选择“审批 / 复核”，再点击“确认复核通过”。
4. 返回 `test01` 会话刷新订单列表。
5. 该行“更多操作 → 确认订单”，核对内容和交期，点击弹窗“确认订单”。
6. 再打开该行“更多操作 → 去发货”，成功提示弹窗点击“我知道了”。

实际结果：复核、确认和发货申请分别返回 200、200、202；订单为“已确认 / 已移交仓库”。销售确认弹窗显示 FG001 可用量 2300，不能据此认定选定发货仓库真实有货。

### A3. 仓库缺货申请：第一处阻断

1. 左侧“库存管理 → 出库管理”。
2. 找到来源订单 `SO-20261013-2DD0B2AD`，点击该行“去发货”。
3. 弹窗选择“成品发货仓 (WH-E2E-1013)”。
4. 等待加载，实际可用量为 0，缺口 1000。
5. 点击“去生产”。

实际结果：`check-and-reserve` 返回 424，错误为 `FULFILLMENT_424_DEPENDENCY_FAILED`，详情 `AVAILABILITY_FACT_MISSING`。弹窗要求重新选择仓库，未创建对应生产需求；重复选择后再次操作仍失败。

仓库 UUID：`d38ac547-8fc0-4e33-b023-cee50cc4d73d`。该结果证明当前选择仓库与权威库存事实之间没有可用的预留事实，不能简单把缺失事实当作已确认零库存。

## 4. 生产需求、计划和工单：实际操作

### B1. 使用预置需求：第二处阻断

1. 左侧“生产管理”，顶部点击“主计划(MPS)”。
2. 找到 `DM-SEED-002`。
3. 行末为图标按钮，悬停查看名称；点击“需求校验”。

实际结果：POST `/api/v1/production/demands/demand-seed-002/validate` 返回 404，“需求不存在或不在当前数据范围内”。需求仍为“待校验”。

代码定位：迁移 `022_business_seed.sql` 的生产 doc_id 为 `demand-seed-002`；JDBC 启动按 doc_id 安装 Map；生产单条查询使用 `TENANT-SHWS:demand-seed-002`。列表按 values 扫描所以可显示，单条命令按复合键查询所以找不到。FQC 预置数据存在同类问题。

截图：[需求校验阻断](artifacts/production-walkthrough-20261013/production-demand-block.png)。

### B2. 独立验收需求准备

为了继续操作，在同一登录会话通过 POST `/api/v1/production/demands` 准备了一条独立需求。这一步是测试数据准备，不是前端已经提供了正式“新建需求”表单。

输入：code=`DM-UI-20261013-01`，sourceType=`MANUAL`，productId=`FG001`，productName=`生产页面验收产品`，qty=`12`，uom=`PCS`，dueDate=`2026-10-20`，factoryResourceId=`FAC-SH-01`。

返回 201；随后刷新“主计划(MPS)”，新需求显示为“待校验”。本次未直接改数据库、浏览器业务状态或返回结果。

### B3. 校验、审批和接收

1. `test01` 在新需求行点击“需求校验”：变为“待审批”，API 200。
2. 仍用 `test01` 点击“异人审批”：API 403，提示制单人不能审批本人需求。这是正确的业务阻断。
3. `reviewer` 会话进入“生产管理 → 主计划(MPS)”。
4. 找到 `DM-UI-20261013-01`，点击“异人审批”：API 200，变为“待接收”。
5. 返回 `test01` 会话，刷新“主计划(MPS)”。
6. 同一需求行点击“计划员接收需求”：API 200，记录 handlerId=test01，变为“待展算”。

注意：当前需求校验客户端传入产品、工厂、BOM、工艺均有效的布尔值；本次校验成功不能证明正式主数据有效性已经由后端实际查询。

截图：[同账号审批被拒绝](artifacts/production-walkthrough-20261013/production-self-review.png)。

### B4. MRP、APS、创建工单

1. 已接收需求行点击“接收后推送 MRP 展算”。
2. 等待生成 `MPS-d273ad22`，状态“已展算”。
3. 在该 MPS 行点击“运行 APS 排程”，等待状态“已排程”。
4. 在该行点击“基于成功排程创建工单”。
5. 页面自动切换“订单与齐套”，显示 `WO-MV6CH9XC5D9E`。

实际结果：MRP 和 APS 均返回 202 / SUCCEEDED，工单创建返回 201；需求、MPS 数量和工单计划数量均为 12。

限制：当前 Java MRP 复制需求为 MPS 行，缺料数组固定为空；APS 生成当前时间的候选。本次只是验证接口和页面状态推进，不代表物料展算或有限产能排程已完成。创建工单时前端随机生成 BOM/工艺快照 UUID，也没有验证它们对应真实已生效快照。

截图：[MRP 接口成功](artifacts/production-walkthrough-20261013/production-mrp-success.png)。

### B5. 齐套检查：第三处阻断

1. “订单与齐套”定位新工单。
2. 点击该行“齐套检查”。
3. 查看页面红色提示。

实际结果：release-impact 接口 HTTP 200，但业务结果 `canRelease=false`，阻断码 `KITTING_NOT_READY`，“物料齐套状态为 未检查”。工单仍为“待齐套检查”，没有出现可继续下发的成功路径。

原因：`createWorkOrder` 没有生成/保存齐套状态，而预检要求 `kittingStatus=READY`。“齐套检查”当前仅调用预检，没有计算并保存齐套、预占物料的后续动作。

补充检查：刷新页面后，MPS 恢复成“已展算”，之前 APS 和已建工单的进度没有在 MPS 行保留；工单列表仍能读取该真实工单。不能从刷新后的 MPS 状态判断该需求从未建过工单。

截图：[新工单齐套阻断](artifacts/production-walkthrough-20261013/production-kitting-block.png)。

## 6. 验收顺序与证据

修复后应重新用一张销售订单连续验收：真实库存事实 → 缺货生产申请 → 需求校验/异人审批/接收 → 实际 MRP 缺料结果 → APS → 工单 → 齐套预占 → 下达 → 领料 → 开工 → 报工 → FQC → 完工入库 → 真实库存回调 → 原出库任务重校验 → 发货 → 结案复核。

当前优先修复：仓库与库存事实映射、预置数据复合键、新工单齐套生成与物料预占；然后接通真实车间动作、FQC 和完工状态恢复，消除原型成功提示与后端事实不一致。

本次保留了新增验收销售订单、需求和工单，没有删除原数据或修改业务实现。原型报工与入库只发生在独立浏览器会话的本地存储。

网络证据：[network-evidence.json](artifacts/production-walkthrough-20261013/network-evidence.json)。包含本次写接口路径、HTTP 状态、业务响应，以及无业务接口请求的原型检查记录；不含访问令牌或密码。
