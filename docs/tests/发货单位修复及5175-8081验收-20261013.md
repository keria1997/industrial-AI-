## 原因

只读查询原 PostgreSQL 确认：销售订单 `SO-20261013-93B19749` 的 FG001 行为 `1 台`，仓库任务 `8d52c409-b405-49b6-9141-0818d9f708cb` 同样使用 `台`；成品主仓的库存事实为 `5 PCS`，版本 2、预留 0、可履约 5。

## 修复

- 前后端共用一致的单件规则：`PCS`、`件`、`台`、`个` 按 1:1 计数兼容。快速开单与历史本地订单转正式订单传规范编码；不会将套或重量覆盖为 PCS。
- 已存在的正式订单、申请和任务保留原始单位、来源快照和数量，不执行数据迁移或重建。预留、实际扣减、完工入库及采购入库使用同一兼容规则。
- 新库存事实和库存流水写入 PCS；不兼容的计量单位变更仍阻断。未增加套、箱、重量或任意包装系数的隐式换算。
- 发货弹窗遇到不兼容单位显示具体产品及两侧单位，禁用发货；允许选择另一发货仓库，旧仓预留不会算入新仓可用量。
