## 2. 管理负责人技能描述

当前项目管理和技术管理职责包括：

1. **需求治理**：核对新增、修改、删除需求，识别业务目标、角色、流程、数据、权限、接口、非功能和验收影响，防止需求遗漏或无记录扩张。
2. **进度审计**：以可执行代码、自动化测试和 API 契约为证据，区分已完成、部分完成、原型完成和未完成；不以页面、Toast、`localStorage`、异步任务记录或 Outbox 表代替真实交付。
3. **任务拆解**：把需求转换为有优先级、依赖、责任角色、交付物、验收标准和状态的任务，保持需求、用例、接口、代码和测试可追踪。
4. **技术治理**：控制前后端模块边界、租户与权限、数据精度、幂等、乐观锁、审计、事件一致性和外部系统适配风险，避免继续扩大 `src/App.tsx` 和生产单体服务的职责。
5. **质量管理**：根据变更风险确定类型检查、单元/API、数据库、前端组件、E2E、构建、分辨率、性能和安全验证范围；只有取得验证结果后才能更新为已完成。
6. **风险与决策管理**：持续登记需求待确认项、外部依赖、架构决策和阻塞条件，明确责任角色、关闭标准和对交付批次的影响。
7. **文档一致性**：每次需求或实现状态变化后，检查 PRD、架构、功能清单、用例、OpenAPI、API 文档和本任务台账是否一致。

## 3. 管理规则

### 3.1 事实优先级

发生冲突时，按以下顺序判断当前行为：

1. 实际代码与自动化测试。
2. `server/docs/openapi.yaml`。
3. 架构文档、需求功能清单和用例。
4. 原始 PRD；PRD 仍是目标范围依据。

发现冲突时必须登记问题并修正文档，不能据此推定需求已经完成。

### 3.2 任务状态

| 状态 | 定义 |
| --- | --- |
| 待评审 | 范围、口径、依赖或验收尚未确认 |
| 待开始 | 已满足进入条件，尚未开始执行 |
| 进行中 | 已有负责人正在交付，且存在可核查进展 |
| 阻塞 | 有明确外部条件阻止继续执行，已记录解除条件 |
| 待验收 | 实现完成，等待规定验证或业务确认 |
| 已完成 | 实现、验证、文档和验收证据均齐备 |
| 已取消 | 经评审退出范围，并保留原因和影响记录 |

### 3.3 需求变更处理流程

每次新增或修改需求时按以下顺序执行：

1. 创建唯一变更编号 `REQ-YYYYMMDD-NN`，记录来源、目的、优先级和原始描述。
2. 先形成“初步功能变更清单”，逐项标明新增、修改、删除或仅澄清。
3. 分析对业务流程、角色权限、数据模型、API/事件、页面、外部依赖、测试、迁移和文档的影响。
4. 更新 `docs/需求功能清单.md`；涉及用户路径时更新 `docs/usecase.md`，涉及接口时同步更新 OpenAPI 和 API 文档。
5. 将功能项拆为执行任务，补齐依赖、责任角色、交付物和可验证完成标准。
6. 实施期间更新任务状态和风险；范围变化必须回到变更评审，不在开发任务中静默吸收。
7. 完成后记录代码、测试、构建、界面或业务验收证据，并写入需求历史。

不能在后台“时刻”自动检查仓库；每次需求变更、代码交付、测试结果或项目复盘发生时，必须按本流程重新核对并更新台账。

### 3.4 进入与完成标准

**进入开发前必须具备：**

- 业务目标、范围、优先级、角色和主流程明确。
- 字段、状态、权限、异常和验收标准可执行。
- API/事件和外部依赖已确认，或有明确的模拟边界。
- 任务依赖、责任角色和测试范围已登记。

**标记已完成前必须具备：**

- 目标代码可执行，原型与正式能力标识准确。
- TypeScript 检查和相关自动化测试通过，前端变更完成构建验证。
- UI 变更检查 `1280x720` 和 `1920x1080`，无重叠和关键文本溢出。
- API 变更已同步两份接口文档，需求状态已同步功能清单和用例。
- 风险、限制、未完成项和验收证据已记录。

## 4. 当前需求进展基线

## 7. 下一阶段目标与初步功能变更清单

### 7.1 阶段目标

下一阶段定义为“**销售—库存—生产—发货首期闭环**”。目标是在保持现有前端整体设计的前提下，建设销售订单和库存履约正式聚合，复用已实现的生产后端，并打通从订单待确认到全量发货的真实业务事实链路。

阶段退出条件：

- 销售订单、订单行、复核/审批和发货申请使用正式后端，刷新后可以恢复。
- 库存可用量、预留、销售出库和库存流水形成正式事实，不再由页面状态模拟。
- 现有生产页面保持整体设计，需求、工单、报工、FQC 和完工动作接入正式 API。
- 缺货生产需求、完工库存事实、重新校验和部分/全量发货可追踪。
- 前端统一处理租户、操作者、权限、Trace、幂等键、ETag、分页和业务错误。
- 核心流程不再以 `localStorage` 或组件状态冒充服务端成功。
- 类型检查、API/集成测试、前端构建和首期闭环 E2E 通过。
- 相关功能清单、用例和接口文档与实现一致。
